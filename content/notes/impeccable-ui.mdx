今日头条这篇介绍的是 Impeccable，一个给 AI Coding Agent 补「设计判断力」的开源项目。它支持的工具有 Claude Code、Cursor、Codex CLI 等，定位不是新组件库，而是让 Agent 在写界面前先知道产品和设计规范是什么。

原文标题强调 GitHub 星标数。星标只能说明关注度，不能说明效果，所以下面只谈它实际提供了什么。

![Impeccable 原文截图：项目定位与主要能力](/shots/impeccable-ui/shot.png)

## 它补的是「设计词汇」，不是组件

官方给它的定位是「The missing design vocabulary for agents」——给 Agent 补一套描述设计的词汇。原文把它拆成四部分：

- 1 个 Skill，负责把设计上下文和命令接入 Agent
- 24 个设计命令，按能力划分，比如 polish、audit、critique、typeset、layout、colorize、animate
- Live Browser Iteration，在浏览器里边看边改
- 61 条确定性检测规则，用来扫具体问题

24 个命令里比较有意思的是一对反向操作：bolder 和 quieter。前者让页面更大胆，后者把过度设计的页面收回来。原文认为这说明它约束的不是某一种风格，而是分寸。

安装方式是 `npx impeccable install`，然后在工具里执行 `/impeccable init`。需要自动检测时可以执行 `/impeccable hooks on`，更新用 `npx impeccable update`。如果不走 CLI，也可以从官方站点下载对应工具的 ZIP 包。

## 先写上下文，再谈风格

Impeccable 的第一步不是让 AI「把页面做漂亮点」，而是建立两份文件。

`PRODUCT.md` 记录产品是什么、用户是谁、要解决什么问题、运行环境、设计约束、语气和可访问性要求。`DESIGN.md` 记录项目自己的色彩、字体、圆角、间距、组件和品牌规则，用来保证 AI 后续新增页面时风格不漂移。

这个顺序是合理的。没有上下文，AI 只能套模板；有了上下文，它至少知道该往哪个方向收敛，以及哪些东西不能改。

## 61 条规则为什么不烧 Token

这套规则最实用的地方，是检测过程不调用 LLM，也不需要 API Key。它直接扫描代码和页面，把问题定位到具体位置。

原文列出的覆盖范围包括：AI 常见的紫色渐变、不合理的动画、深色 Glow、字体问题、对比度、间距、点击区域过小、标题层级、卡片嵌套、页面布局。这些恰好是 AI 生成页面时反复出现的套路，靠人眼一页页看很费时间，靠模型审又贵又不稳定。

确定性的规则扫描做不了审美判断，但能把「一眼就能看出不对」的问题先清掉，剩下的再交给人或模型。

## 适合谁，不适合谁

原文的判断是：后台、SaaS、Landing Page，以及已有项目的改造，比较适合用它；只写一次性 Demo 的场景没必要引入。

我认同这个划分。一次性 Demo 的寿命可能就是几个小时，建立 PRODUCT.md、DESIGN.md 再逐轮打磨，成本不划算。反过来，一个要长期维护的后台，设计规范一旦被 AI 带偏，后面每次新增页面都要还债。

## 我还没搞懂的部分

61 条规则的具体判定逻辑我没有读源码，不知道误报率有多高。规则扫描出来的「问题」里，有多少其实是合理的设计选择，需要实际跑一遍才知道。

另外，`PRODUCT.md` 和 `DESIGN.md` 写得多细才够用，原文没有给出可直接照抄的模板。太粗起不到约束作用，太细又会变成另一份需要维护的文档。
