今日头条这篇介绍的是 Mnemosyne OS 7.0.0，一个本地优先的 AI 记忆系统，最大的特点是零依赖：不装 numpy、torch，也不用向量数据库，只靠 Python 标准库运行。

原文标题用了「全球顶尖」「国内唯一」和「爆省 Token 90%+」这类说法。正文没有给出 Token 节省的测算过程，作者本人也是仓库维护者，所以这些结论要打折看。下面只整理它具体做了哪些设计。

## 零依赖意味着什么

大部分 AI 记忆方案的做法是加依赖：向量库、嵌入模型、云端服务。Mnemosyne 反着走，Python 3.8+ 的干净环境里可以直接运行：

```python
MemoryBrain("./mem", enable_embeddings=False)
```

安装只需要一条 `pip install mnemosyne-os`。原文给出的适用场景是 Serverless 冷启动、离线环境，以及数据不能出本机的场景。

代价也很明显：不开嵌入模型，语义召回能力会弱一些，主要靠关键词和结构化检索兜底。它换来的好处是部署简单、启动快、没有外部服务依赖。

## 哈希链让「记忆被改过」可被发现

这是它和普通记忆方案最不一样的地方。每条记忆写入时都会生成一个 SHA-256 哈希，并与上一条记忆的哈希链接起来，形成一条链。

`verify-integrity` 会遍历整条链。只要中间有一条记录被改动，哪怕只是改了一个标点，链就会断，并且能定位到具体是哪条记录。`ledger-audit <memory_id>` 则可以查单条记忆的完整生命周期。

原文把定位放在审计和隐私合规上。这个方向是成立的：对需要留痕的场景来说，「能证明记录没被动过」往往比召回率更关键。

## 遗忘不是删除，是降温

Mnemosyne 把记忆分成热、温、冷三层。低频数据会被迁移到冷存储，而不是直接删掉，之后仍然可以通过哈希链追溯。

这个设计解决的是记忆系统的一个常见矛盾：上下文窗口有限，不可能把所有历史都塞进去；但直接删除又会丢掉可能还有用的信息。分层降温相当于给「暂时不用」和「永远不要」划了一条界线。

## MCP、中文和安全检查

原文还提到几块具体能力：

- 原生作为 MCP Server 运行，启动命令是 `python -m mnemosyne.webui.mcp_server --brain-dir ./mem`，对外暴露 retain、recall、audit 等 13 个工具
- 支持多租户命名空间隔离，不同项目或用户的记忆互不干扰
- 中文检索用二元分词（Bigram）加 FTS5，再配一个内置同义词词典，不需要额外的 NLP 预处理库
- 写入前经过 Security Notary 检查，包括不可见 Unicode 字符（防 Prompt 注入）、HTML 注入、敏感凭据检测和字段级脱敏

这些能力拼在一起，说明它的定位偏基础设施，面向需要审计、隐私合规和可嵌入式部署的开发者，而不是开箱即用的消费级产品。原文给出的仓库地址是 `github.com/FrankHu-HK/mnemosyne`。
