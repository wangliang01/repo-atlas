## 它是什么

SolidCraft 是一个用纯 Rust 实现的开源参数化 3D CAD 应用。用户画草图、加约束、按特征时间线拉伸或旋转实体，改一个尺寸后模型整体重建。它的使用面不只桌面：同一套命令可以跑在桌面应用、浏览器、无头 CLI 和 MCP 服务器里，因此既面向机械与产品设计者，也面向想把建模接进脚本或 AI Agent 工作流的开发者。README 对成熟度的描述是“Early but usable for simple parts”，并用 76 个公共参考零件做校验，其中 75 个的体积、面积、质心和外接盒与解析值或 FreeCAD 计算结果一致，剩余一个是被跟踪的 bug。许可为 MIT 或 Apache-2.0，二选一。

## 怎么上手

最直接的方式是从 Releases 下载安装包：Windows 用 MSI，macOS 用通用 DMG（Apple 芯片和 Intel），Linux 用 AppImage 或 `sudo snap install solidcraft`，也可以直接在浏览器里打开 Web 版试用。README 特别说明 Windows 安装包目前未签名，SmartScreen 可能拦截，需要点“更多信息”再“仍要运行”。从源码构建需要 Rust 工具链：

```sh
cargo run --release -p solidcraft -- --sample      # 带示例零件的桌面应用
cargo run --release -p solidcraft-cli -- commands  # 列出命令注册表
cargo run --release -p solidcraft-cli -- run examples/bracket.json --out bracket.step
cargo xtask ci                                     # fmt、clippy、测试、图标、资源、wasm
```

如果想让 Agent 通过 MCP 驱动建模，README 给出的注册命令是：

```bash
claude mcp add solidcraft -- solidcraft-cli mcp
```

较旧的 Windows 安装器可能没把 `solidcraft-cli` 放进 PATH，此时要写完整路径，例如 `C:\Program Files\SolidCraft\solidcraft-cli.exe`。更多构建选项、Windows 交叉编译和浏览器构建在 `docs/building.md` 中，README 未在正文展开。

## 值得注意的设计

第一层设计是把 UI 操作收敛成命令。脚本就是一个 JSON 命令列表，用 `solidcraft-cli run` 执行；桌面、CLI、浏览器命令 API 和 MCP 走的是同一个命令注册表。这意味着一个建模步骤既能手动点出来，也能被脚本复现，还能被 Agent 调用，不必为每条通道维护不同实现。MCP 服务还有两种模式：无头模式自己开设计会话，`--connect` 则驱动正在运行的桌面应用，方便用户旁观 Agent 的操作。

第二层是围绕参数化时间线的特征体系。草图包含直线、圆弧、样条和文字，由项目自研的约束求解器求解，尺寸可以绑定参数和带单位的表达式；特征覆盖拉伸、旋转、扫掠、放样、圆角、倒角、抽壳、拔模、孔、螺纹、阵列、镜像、分割与合并。装配支持关节、运动研究、接触集、干涉检查和质量属性，另有钣金与塑料外壳特征。导出的格式包括 STEP、IGES、3MF、STL、OBJ、glTF 和 URDF。

第三层是实验性的 WebAssembly 插件运行时。插件包由一个 `plugin.json` 和一个 `.wasm` 组件组成，接口是 WIT 包 `craft:plugin@0.2.0`；安装、启用或打开设计都不会执行插件代码，必须由用户显式 `plugin.run`。`plugin.inspect` 会返回一个 approval 哈希，绑定 manifest 与组件字节，更新插件后必须重新审查。执行有燃料、内存和时限上限，默认单次 10,000,000 fuel、64 MiB 和 5000 ms，宿主上限更高；编辑在设计的隔离副本上进行，只有成功调用才作为一个 Undo 步骤合并，失败则保留原设计。跨出当前设计的命令被划分为 `file`、`doc`、`app`、`plugin` 四组，manifest 不声明且用户未授权时一律拒绝。

## 边界与风险

README 把“早期”写得很明确：简单零件可用，复杂场景仍需验证；插件接口处于 0.x，次版本可能破坏上一版，浏览器执行、自动下载更新、自定义面板和插件自定义参数化特征都还是未来工作，命令组的授权界面也尚未提供。Windows 构建未签名，macOS 已签名并公证，Linux 包情况按下载页说明。升级方面，0.11 到 0.14 之间的版本需要手动下载一次，之后才能用应用内更新。

许可上主体是 MIT 或 Apache-2.0，但品牌与界面单独放在 `LICENSE-BRAND` 下：把 UI 套件、图标、主题、名称和 logo 用在本项目之外，需要维护者书面许可。README 还声明项目与 Autodesk、Dassault、PTC、Siemens 等厂商无关联，商标只用于描述兼容性。README 未说明最低操作系统版本、长期支持政策、插件沙箱之外的安全审计结论，也没有给出跨平台渲染一致性或大规模装配性能的数据；在把它用于生产建模前，应先用自家零件跑一遍校验流程。
