## 它是什么

World Monitor 是一个实时全球情报仪表盘，把 AI 聚合的新闻、地缘政治监测和基础设施跟踪放进同一个态势界面。README 把它定位成统一态势感知界面：新闻按地区和主题组织，并被 AI 汇总成简报；地图同时提供 3D 地球和平面视图；军事、经济、灾害与升级信号可以跨流关联；另有一个名为 Country Instability Index 的指数，给出 31 个 Tier-1 国家的 CII v14 分数、区间和近 24 小时变动。

它不只是一个网页。README 列出的入口包括：world、tech、finance、commodity、happy、energy 六个站点变体；Windows、macOS 和 Linux 的 Tauri 桌面应用；运行 `npx worldmonitor` 的终端面板；npm 与 Homebrew 分发的 CLI；Python、Ruby、Go 三个 SDK；托管在 https://worldmonitor.app/mcp 的 MCP server；以及 https://api.worldmonitor.app 的 REST API。终端面板提供世界地图、新闻、市场、冲突、军机、网络、气候、预测市场和直播电视，README 说它不需要 API key，并支持鼠标与配色主题。

给谁用？README 没有直接写用户画像，但从入口设计可以推断：需要持续跟踪全球事件的分析人员、研究者，以及想把情报接进脚本或代理的开发者。编辑判断：和普通新闻聚合器相比，它的差别不在读新闻，而在把多类信号叠到同一张地图上，并提供可编程入口。

README 还特别声明，World Monitor 的名称和 wordmark 指向官方站点，不要把 fork 包装成官方网站。

## 它替掉了什么麻烦

它替掉的是「开十几个标签页分别看新闻、航班、行情和地图，再靠人脑把事件对上」这套手工汇总。README 没有交代出现之前的标准做法；编辑判断：过去跟踪全球事件，通常是在新闻网站、航班追踪、市场行情、灾害和网络状态之间来回切换，时间和地点对不上，关联全靠记忆；企业级情报面板又往往价格高、接入门槛高。

它的切入点是「同一张地图叠多类信号」。README 说新闻、地缘政治、金融、能源、气候、航空、网络、军事、基础设施和新闻情报来自带署名的上游，按 provider、feed-tier、license-posture 和 collection-method 编目。编辑判断：这把原先分散的视图收进一个界面，代价是同一张图上的数据在授权、时效和可靠性上并不等价，需要看编目才能判断能否引用。

和同类方案的差别，README 没有列举竞品，也没有做功能对比。编辑判断：从 README 能确认的差异是六个站点变体、一个桌面二进制内切换变体、终端面板不需要 API key，以及 MCP、REST、三个 SDK 等可编程入口；这些是「多入口」的差异，不等于数据更准或更快。README 未说明各上游的准确率或更新 SLA。

## 跑起来要几步

最快的方式是用 Docker 自托管完整栈：

```bash
curl -fsSL https://www.worldmonitor.app/install.sh | bash
```

README 说脚本会克隆仓库（或复用已有 checkout）、生成所需密钥、启动仪表盘、Redis、AIS relay 并灌入公开数据，完成后打开 http://localhost:3000。API key 是可选的。脚本支持 `--dir`、`--port`、`--no-seed`、`--no-build` 等参数，需要放在 `bash -s --` 之后传入。README 建议生产环境先读 SELF_HOSTING.md。

本地开发要求 Node.js 24，仓库的 .nvmrc 固定了版本。README 特意提醒：Debian 12 和 Raspberry Pi OS 自带 Node.js 18 与 npm 9.2.0，会在 `npm install` 时报 `Invalid comparator: file:vendor/braces`。本地启动命令是：

```bash
git clone https://github.com/koala73/worldmonitor.git
cd worldmonitor
npm install
npm run dev
```

开发服务器同样在 3000 端口，可用 .env.local 里的 `DEV_PORT` 覆盖。应用无需环境变量即可运行，但部分特性数据源需要凭据，清单在 .env.example。变体开发用 `npm run dev:tech`、`dev:finance`、`dev:commodity`、`dev:happy`、`dev:energy`。

如果只想在终端看数据，直接运行 `npx worldmonitor`；要装 CLI 可用 `npm install -g worldmonitor` 或 `brew install worldmonitor`，然后例如 `worldmonitor risk IR --api-key wm_xxx`。MCP 的 `tools/list` 是公开的，`tools/call` 需要用 `X-WorldMonitor-Key` 头或 OAuth 认证；API key 在 worldmonitor.app/pro 获取。桌面端提供 Windows、macOS Apple Silicon、macOS Intel 和 Linux AppImage（x64 与 ARM64）下载，装好后在应用内切换变体。自托管的部署选项包括 Vercel、Docker 和静态站点。

常见卡点一是 Node 24 的硬要求，二是部分功能在没有对应凭据时会缺数据，README 没有逐一列出哪些功能缺 key 会降级。

## 它把复杂度放在哪

复杂度放在「两套地图引擎共享目录 + 分析层做信号收敛 + 一份代码支撑多入口」这三处。README 说 3D 地球使用 globe.gl 与 Three.js，平面地图使用 deck.gl 与 MapLibre GL，但地图图层目录是共用的。这样同一批数据层可以在两种视图间切换，而不是为每种视图维护两套渲染逻辑；README 把这一点列为 dual map engine，并强调共享 catalog。

分析层不只做信息展示，还做信号收敛。README 说 Country Instability Index 提供 CII v14 分数、区间和 24 小时变动，跨流关联把军事、经济、灾害和升级信号放在一起看。README 没有在正文写这些指标和算法的细节，而是指向完整文档。编辑判断：应把指数理解为一个有版本号的模型输出，而不是原始事实。

单一代码库支撑多种交付形态。README 说所有站点变体和桌面二进制来自同一份代码、走同一个发布流程；桌面端只有一个 Tauri 2 二进制，安装后可在应用内切换变体，刻意不提供按变体拆分的下载包。终端面板与 CLI 发布为 npm 包，由 `cli-v*` 标签从 `cli/` 目录发布。技术栈包括 Vanilla TypeScript、Vite、globe.gl + Three.js、deck.gl + MapLibre GL、Tauri 2（Rust）加 Node.js sidecar、Ollama / OpenRouter、浏览器侧 Transformers.js、Protocol Buffers 与 sebuf HTTP 注解，以及 Redis（Upstash）、三级缓存、CDN 和 service worker。编辑判断：这套组合针对的是多入口、强时效的数据产品，复杂度主要在构建和部署，而不是单个页面。

面向代理的细节也写进了交付物。README 说 MCP server 通过草稿版 `io.modelcontextprotocol/skills` 扩展发布 `skills/list`、`skills/get` 和 `skill://` 资源读取，站点还提供 llms.txt、agent-skills manifest 与 api-catalog 三个发现文件，CLI 可以用 `npx worldmonitor tools` 直接列出全部 MCP 工具。编辑判断：这些入口让它能被脚本和代理直接消费，但也意味着上游数据的授权和时效问题会原样传给调用方。

代价是多入口要分别维护。README 说终端面板与 CLI 的版本节奏与 Web 端分开，支持状态表把六个站点、桌面二进制和 npm 包都标为 Stable，issue 走同一个 backlog；但 README 未说明各平台的功能差异。

## 什么时候别用它

它不适合把关键决策只押在这个面板上的团队，也不适合无法接受 AGPL 义务的闭源商业场景。代码采用 AGPL-3.0-only，README 的表格说明个人、研究、自托管、fork 和商业使用都可以，但商业与 SaaS 需要遵守 copyleft 和源码开放义务；如果需要闭源专有使用或官方品牌授权，要单独获得商业或商标许可。README 还明确要求不要把自己的 fork 包装成官方网站，版权归作者 Elie Habib 所有。

自托管的一行安装脚本通过 `curl | bash` 执行，生产环境应先阅读脚本与 SELF_HOSTING.md，并注意脚本默认会克隆、生成密钥和灌数据。README 未说明各上游数据源的准确性保证、更新频率 SLA 或断供后的降级策略，只说明会聚合带署名的来源，并提供数据源目录。编辑判断：面板适合做态势感知的起点，不适合当唯一事实来源。

环境要求偏严格：Node 24 是本地开发的硬前提，旧发行版会导致安装失败。桌面端虽有 Windows、macOS 和 Linux 构建，README 未说明各平台的功能差异或签名策略；终端面板与 CLI 被标为稳定，但版本节奏与 Web 端分开。

数据与安全方面，README 说航班数据由 Wingbits 提供；安全章节记录了一位研究者披露的三类问题，涉及 IPC 命令暴露、renderer 到 sidecar 的信任边界和 fetch patch 的凭据注入，说明桌面端的攻击面需要认真对待。README 未说明本地缓存和凭据的保存位置与清理方式。编辑判断：如果桌面端要接触敏感账户或内网，应先读 SECURITY.md 并评估这些边界。
