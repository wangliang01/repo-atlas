## 它是什么

HyperFrames 是 HeyGen 开源的一套 HTML 原生视频框架。README 的定位是「写 HTML，渲染视频，为 Agent 而建」。开发者把一段视频定义成一个 HTML 合成，用数据属性标注时间、时长和轨道，动画由 GSAP、CSS、Lottie、Three.js、Anime.js、WAAPI 或自定义适配器驱动；渲染器用无头 Chrome 逐帧 seek，再用 FFmpeg 编码成 MP4，同样输入得到同样输出。

它面向希望用代码、CI 或 AI 编码 Agent 程序化生产视频的开发者与内容团队，不要求 React，也没有专有 timeline 格式。项目以 Apache 2.0 发布，README 强调没有按次渲染费或商用门槛。除开源框架外，HeyGen 还提供 Studio 桌面应用和托管服务：Studio 有免费计划，Pro 每月 25 美元，增加 HeyGen Video 1、Seedance 2.5、Lyria 3 Pro 等模型和每月 25,000 credits。README 把这些商业服务与开源渲染引擎分开描述，选型时也要分开看。

README 把使用方式分成三条：不写代码的人用 Studio 桌面应用，用自然语言描述或拖入素材来编辑；编码 Agent 通过 skills 使用；Claude、ChatGPT 或 Grok 的聊天连接器处于 beta，其中 ChatGPT 需要 Business、Enterprise 或 Edu 工作区。

## 它替掉了什么麻烦

它替掉的是「做一条带动效的视频，只能在时间线软件里手拖，或者写一套 React 工程」的麻烦。README 未说明传统剪辑软件的具体工作流；编辑判断：常见做法是在 After Effects 这类工具里手工搭时间线、导出 MP4，改一句文案就要回到工程里找图层；要批量或自动化，就得写脚本或另建一套渲染服务，视频逻辑和代码逻辑是两份。

README 说 HyperFrames 受 Remotion 启发，两者都用无头 Chrome 与 FFmpeg 渲染，主要差别在创作模型：Remotion 押注 React 组件，HyperFrames 押注人和 Agent 都容易写的普通 HTML。前者需要 bundler，后者没有构建步骤；前者处理 wall-clock 动画需要小心，后者通过适配器把动画变成可 seek 的帧。编辑判断：这替掉的是 React 工程的门槛，把视频降成「一个可预览的 index.html」。

和手工剪辑相比，它替掉的是不确定性。README 说渲染器在无头 Chrome 中逐帧定位，再由 FFmpeg 编码，因此同一输入产生同一视频，适合 CI、回归测试和自动渲染；这和基于 wall-clock 播放再录屏的方案不同。编辑判断：对于要把视频生产放进流水线的团队，这比「每次导出肉眼看一遍」更可靠。

## 跑起来要几步

使用编码 Agent 是 README 推荐的方式，先安装 skills：

```bash
npx skills add heygen-com/hyperframes     # 在 picker 里选 Core Skills
# 或非交互式安装：
npx hyperframes skills update
```

Claude Code 用户也可以走插件市场：

```bash
claude plugin marketplace add heygen-com/hyperframes
claude plugin install hyperframes@hyperframes
```

不依赖 Agent、直接命令行建项目则是：

```bash
npx hyperframes init my-video
cd my-video
npx hyperframes preview      # 浏览器实时预览
npx hyperframes render       # 渲染为 MP4
```

运行要求是 Node.js 22+ 和 FFmpeg。云端渲染用 `hyperframes cloud render`，自建分布式渲染可以部署到 AWS Lambda。若要把仓库完整 clone 下来开发，注意黄金回归基线用 Git LFS 存放，约 240 MB 的 `output.mp4`，需要先安装 Git LFS；只取源码可以设置 `GIT_LFS_SKIP_SMUDGE=1` 跳过。

README 还提供成片分享：`npx hyperframes auth login` 后运行 `npx hyperframes share`，可选择谁能打开审阅链接；`share --update` 把改动变成新版本，`share --manage` 管理网页设置。常见卡点是 skills 注册表可能落后 `main` 数小时，`skills add` 解析的是 skills.sh 的 blob，而 `npx hyperframes skills update` 会按与 CLI 匹配的 release tag 安装，后者更适合对齐版本。

## 它把复杂度放在哪

复杂度放在「一层很薄的合成模型」和「一层很厚的工具链」上。README 说合成模型非常薄：一个 `div#stage` 带 `data-composition-id`、`data-start`、`data-width`、`data-height`，每个视频、标题或音频元素带 `data-start`、`data-duration`、`data-track-index`，音频还可带 `data-volume`。动画库把自己注册到 `window.__timelines`，渲染器按时间点 seek 后逐帧截取。编辑判断：因为合成就是普通 `index.html`，没有构建步骤，浏览器里能直接播放和预览，Agent 也只需要写 HTML，不必理解专有工程格式。

确定性来自渲染路径而不是运行时录制。README 说明渲染器在无头 Chrome 中逐帧定位，再由 FFmpeg 编码。编辑判断：代价是它对页面里的非确定性来源很敏感，而 README 没有说明字体、媒体解码器或 GPU 差异会怎样影响结果。

包结构把职责拆成可替换的层次。README 说 `@hyperframes/core` 管类型、解析器、生成器、linter、运行时和帧适配器；`@hyperframes/engine` 用 Puppeteer 与 FFmpeg 做可寻址的页面转视频；`@hyperframes/producer` 负责完整捕获、编码和混音流水线；此外还有浏览器编辑器 studio、可嵌入的 `<hyperframes-player>` Web Component、WebGL 着色器转场和 AWS Lambda SDK。README 还说围绕框架发布了 9 个 skills 和约 450 个可安装的现成区块，覆盖转场、字幕、图表、地图和 3D。

README 对 9 个技能的分工写得很细：`/hyperframes` 是必须先读的渲染契约与工作循环，`/hyperframes-cli` 负责脚手架、检查、预览、渲染和失败恢复，`/hyperframes-registry` 覆盖约 450 个区块，`/media-use` 负责音乐、音效、图像、配音等素材，`/reverse-any-video` 把任意视频重建为可编辑项目，`/style-sampling` 提供五种成熟风格；`/figma`、`/slideshow`、`/remotion-to-hyperframes` 按需安装。frame.md 则把网页设计系统转换成面向镜头的 DESIGN.md 超集。编辑判断：这种薄合成加厚工具链的设计，让 Agent 的出错面集中在 HTML 与动画契约上，但也意味着复杂效果要靠 catalog 或自定义适配器补齐。

## 什么时候别用它

开源的是框架，不是 HeyGen 的托管模型。README 中提到的 Studio 免费计划、每月 25 美元的 Pro、积分以及 HeyGen Video 1、Seedance 2.5、Lyria 3 Pro 等模型属于商业服务，和 Apache 2.0 的渲染引擎不是同一件事。云端渲染和 Lambda 渲染也需要额外的云账号、费用和部署配置。

README 对技术细节的覆盖偏营销：它没有给出浏览器与操作系统支持矩阵，没有说明字体、媒体解码器或 GPU 差异对「确定性」的影响，也没有公开渲染吞吐和并发基准。Node 22+ 与 FFmpeg 之外的系统要求、支持政策、发布节奏都属于 README 未说明的内容。README 未说明本地渲染的并发调度、失败重试和资源上限，也没有给出云端渲染的计费细则；Lambda 路径需要自己的 AWS 账号和部署知识。仓库迭代很快，skills 注册表可能落后 `main` 数小时；社区 skills 由第三方维护，使用前需要自行审查。示例和模板中可能含第三方素材，各自许可以仓库文件为准，不能默认都按 Apache 2.0 处理。

许可证是 Apache 2.0。隐私方面，使用云端渲染、Studio 或 `share` 会把项目或成片交给对应服务，README 未展开这些路径的数据留存与访问控制，团队使用前需要自行评估。编辑判断：它适合愿意用 HTML 和代码管理视频、需要确定性渲染或想把视频生产放进 CI 的团队；不适合需要成熟云端渲染、复杂后期合成，或完全不想碰前端代码的纯剪辑用户。
