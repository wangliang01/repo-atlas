## 它是什么

OpenFilm 是一个开源的 AI 视频 Agent，README 的原话是 “The open source AI video agent.”。它把任意编码 Agent 变成视频 Agent，并提供四个可以手动修改的编辑器：Screening 看整片、Edit 剪时间线、Canvas 做规划板、Color 调色。你和 Agent 操作同一部片子，改动实时互相可见；Agent 承担找素材、写镜头、剪时间线的大部分工作，你负责指位置、提要求，或者直接上手改。

它由四部分组成：Agent（Claude Code、Codex、其他编码 Agent，或桌面 App 内置的那个）、四个共享同一部片子和同一个素材库的编辑器、把插件/技能/素材/示例都当作普通文件夹的 Community 扩展体系，以及以 `film.html` 为核心的工程格式。面向做短视频、产品发布片、演示视频的人，尤其是手上已经有编码 Agent 的开发者。产物是一个包含 `film.html` 的工程文件夹，可以继续编辑，也可以导出视频，或把时间线交给专业剪辑软件。

## 它替掉了什么麻烦

它替掉的是“AI 生成整段、人再拿去剪”的接力式流程。README 没有回顾旧工具链；编辑判断：过去用 AI 生成视频，通常先拿到一段成片，再进剪辑软件二次加工，想让 AI 改一个具体位置，只能重新描述、重新生成，人的细调很难带回来；每改一处都要整段重来，改十次就生成十次。

README 用三句承诺对准这些痛点：改动实时互见（“you see it as it happens”）、可以指着任何东西说话（clip、某一刻、时间线的一段、画面里的一块、一行字幕、画布上一张卡片），以及“你的修改仍然属于你”——手动改的文字、颜色、位置、尺寸会存进 clip 的 `overrides`，Agent 重写页面代码也不会覆盖。和同类方案的差别，README 只说明了一点：它不需要 Remotion 或 HyperFrames 这类把组件转成帧的框架，镜头本身是网页，`frame(t)` 直接画出第 t 秒。README 未点名其他视频 Agent 产品，也未给出功能对比。编辑判断：真正的分水岭不是“AI 会不会剪”，而是人的修改能不能在 Agent 迭代中活下来。

## 跑起来要几步

两条路，桌面 App 最省事，用自己的编码 Agent 则三步，取决于你手上有没有现成的编码 Agent。桌面 App 从 GitHub Releases 下载 macOS 或 Windows 版本即可，README 称所需组件连同内置 Agent 一起打包，已经用 Claude Code 或 Codex 的话也能直接接上。用自己的编码 Agent 则三步：确认 Node 22.2+ 和 ffmpeg，执行安装 Skill 的命令，然后直接对 Agent 说要什么。

```bash
npx skills add openfilm/openfilm
```

README 给的示例口令是 “Make a 20-second launch video for my CLI, with music.”。预期结果是 Agent 自己找素材、写每个镜头并剪在一起，你在 OpenFilm 里实时看到变化；四个编辑器打开的始终是同一部片子。README 未给出安装耗时或项目大小。

常见卡点：README 要求 ffmpeg，却未说明怎么装；桌面端内置 Agent 用哪个模型、要不要登录或 API key，README 未说明；Canvas 里“用你自己的服务生成”具体指哪些服务，README 未说明；没有桌面 App 时，Agent 能调到什么素材生成能力，取决于你给编码 Agent 配了哪些工具，README 未列出清单。想从源码运行或提 PR，README 指向 `CONTRIBUTING.md`。

## 它把复杂度放在哪

复杂度放在工程格式和“人机共写同一份文件”的同步上。一部片子就是一个文件夹，里面有一个 `film.html`；时间线是若干 `<section>`，每节放 clip，位置和尺寸用 CSS 写。README 的示例长这样：

```html
<section>
  <video src="assets/footage.mp4#t=12,18" at="4"
         style="left: 160px; top: 90px; width: 1600px; height: 700px"></video>
</section>
```

每个镜头是一个网页，只暴露一个入口 `frame(t)`，用浏览器能画的任何东西（three.js、WebGL、canvas、SVG、CSS、GSAP、视频）画出第 t 秒的画面。README 强调同一个 `t` 必须得到同一张图，因此在任何机器上渲染一致，Agent 可以逐帧检查。另一层关键抽象是 `overrides`：手动改动不进页面代码，而进 clip 的 overrides；README 的示例里，override 针对的是 `h1` 的文字与颜色。README 描述的数据流可以概括为三条并行：Agent 改页面与工程，人改 overrides，所有编辑器读同一份工程与素材库；本地素材是链接而非复制，移动后能重新找到。

代价也在这里。编辑判断：`frame(t)` 的确定性意味着镜头作者要自己保证画面完全由 t 决定，随机、异步加载和实时状态都会破坏“同 t 同图”；`film.html` 既是数据又是代码，想发挥手动编辑和 overrides 的价值，就得理解这套结构。编辑判断：Community 降低了扩展门槛——插件、技能、素材、示例都是普通文件夹，官方编辑器本身也按插件构建——代价是 README 未说明审核机制或兼容性承诺。

## 什么时候别用它

编辑判断：三种人别急着用它——不想理解工程文件的、需要专业 NLE 级流程的、桌面不是 macOS/Windows 的。许可证方面，README 只提供了指向仓库 LICENSE 文件的徽章，未说明具体许可证名称与条款。平台方面，桌面 App 只提供 macOS 和 Windows 安装包，Linux 未提及；Skill 路径要求 Node 22.2+ 与 ffmpeg。显卡、内存、磁盘等硬件门槛，README 未说明；桌面端的自动更新和系统版本下限，README 也未说明。

隐私与成本取决于你接的服务：素材生成和剪辑判断调用你配置的模型与工具，README 未说明费用、额度、数据处理方式和隐私边界；Agent 会去找 “footage, music and voices”，OpenFilm 也自带免费音乐、音效、声音和贴纸，但这些自带素材的授权范围 README 未说明。编辑判断：商用发布前应逐项核对素材许可证，Agent 从网上找到的素材同样要查。

运维上，README 未说明是否需要账号、联网或后台服务。导出到 Final Cut Pro、Premiere Pro、DaVinci Resolve 时能保留多少效果，以及导出视频的分辨率、码率、编码格式，README 均未说明。不适合谁：完全不想碰工程文件、只想要一句话出片的人（编辑判断：要发挥手动编辑和 overrides 的价值，仍得理解 `film.html`）；需要复杂实拍叙事、精细多轨音频或团队审片流程的团队（编辑判断：这类工作仍应由专业 NLE 承担）；以及桌面环境不是 macOS/Windows 的人。
