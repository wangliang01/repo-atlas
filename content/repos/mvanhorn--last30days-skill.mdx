## 它是什么

`/last30days` 是一个跨平台调研 Skill，解决的是「最近 30 天大家到底在聊什么」这个问题。它并行搜索 Reddit、X、YouTube、TikTok、Hacker News、Polymarket、GitHub、arXiv、Techmeme、LinkedIn 等来源，按点赞、互动量和真金白银的赔率排序，再由 AI Agent 合成一份带引用的简报。README 的定位很直接：Google 聚合编辑，它搜索真人。适合会前做人物或公司背调、跟踪 AI 圈子动态、比较工具，以及在产品发布前看社区反馈。

它不是一个搜索 API，而是一套跑在 Agent 里的技能包：运行时代码在 Python 引擎里，技能规范以 `skills/last30days/SKILL.md` 为准。和普通聚合搜索的差别是它保留原始互动数据：Reddit 的高赞评论、YouTube 的完整转录、TikTok 文案、Polymarket 赔率，而不只是标题和链接。README 称 v4 还会读公司的招聘页和美国专利，从中推断尚未发布的方向。

## 它替掉了什么麻烦

它替掉的是「为了跟上 AI，手动在 Reddit、X、YouTube 之间一页页翻」的调研；README 说作者做它的动机正是「跟上 AI」：这个领域每天都变，Reddit 和 X 上的玩家总是最先掌握，而模型训练数据比社区认知晚几个月，想要更好的提示词就得自己去翻这些平台。README 把这种做法概括成一句对照：Google 聚合的是编辑，它搜索的是真人。

README 说这件事以前没有现成解，是因为平台各自为政：Google 搜索不碰 Reddit 评论和 X 帖子；ChatGPT 与 Reddit 有合作，但搜不了 X 和 TikTok；Gemini 有 YouTube 却没有 Reddit；Claude 原生一个都没有。每个平台都有自己的 API、token 和鉴权，是一座座围墙花园。它的解法不是造一个更好的搜索引擎，而是让你带上自己的 key 和浏览器登录态，把十几个互不相连的平台桥接给同一个 Agent。这也是为什么它把「带自己的 key」当成前提，而不是内置一套共享凭据。编辑判断：和「用一个搜索 API 聚合结果」相比，它的差别是保留原始互动数据，而不只是标题和链接。

## 跑起来要几步

最短路径是 Claude Code 的插件市场：

```
/plugin marketplace add mvanhorn/last30days-skill
/plugin install last30days
```

Codex、Cursor、Copilot、Gemini CLI 等 50 多个 Agent Skills 宿主用 `npx skills add mvanhorn/last30days-skill -g`，`-g` 表示装到用户目录、所有项目可用。claude.ai 网页版需要先下载 `last30days.skill` 再到 Customize > Skills 上传，并开启「Code execution and file creation」。Claude Desktop 则下载对应平台的 `.mcpb` 拖进扩展，且要求 PATH 上有 Python 3.12+；README 说明 Claude Desktop 的 Windows 支持尚未完成。

第一次运行不需要配置：Reddit（含评论）、Hacker News、Polymarket、GitHub 直接可用，公司话题还会带上专利和招聘页。跑一次 `/last30days` 后，设置向导能在约 30 秒内解锁 X、YouTube、TikTok、arXiv、Techmeme 等来源。常见卡点有三个：Claude Code 不会去重不同安装方式，同时装了插件市场和 `npx skills` 会出现两个 `/last30days` 条目；X 需要 `X_BEARER_TOKEN`、浏览器登录态或其他 key；YouTube 落字幕要装 `yt-dlp`。研究结果默认写到 `~/Documents/Last30Days/`，可用 `LAST30DAYS_MEMORY_DIR` 或 `--save-dir` 改；`--save-suffix` 用来区分同一话题的多个版本，`--output` 则指定渲染结果的精确路径。

## 它把复杂度放在哪

整条数据流分七步：解析话题涉及的账号、仓库和社区；多查询并行抓取；按 engagement、相关性和新鲜度打分；抓取正文、转录和评论；把同一事件在多个平台的内容合并成一个 cluster；合成简报并逐条标注来源；最后让当前会话基于这份材料继续追问。

排序机制是它的核心取舍。README 明确用「真人用注意力和钱投票」替代编辑权重：1,500 赞的 Reddit 帖强于没人读的博客，66,000 美元成交量的 Polymarket 赔率比评论员猜测更难反驳。工程上，引擎用 Python 3.12+，X 搜索依赖内置的 Node.js Bird 客户端，TikTok 等平台可走 ScrapeCreators。技能支持 `--emit=json` 输出稳定版本的机器可读结果，`--preflight` 在不读 cookie、不写文件的前提下预览配置来源和计划写入。

发现模式是另一条路径。问 `/last30days what's exploding in AI agents?` 时，它会扫 Reddit 分类列表、Hacker News 榜单、Digg 故事和已登录的 X，由 Agent 判断哪些话题值得追，返回 5 到 10 个按速度排序的话题、动量标签，以及可直接运行的跟进命令。脚本场景用 `--discover "AI agents"` 走一次性的确定性结果，但不生成内容角度。

README 列出的来源远不止开头那几个：还有 Instagram Reels、Digg、Yahoo Finance、Meta Ads、StockTwits、Threads、Pinterest、Xiaohongshu、Bluesky、Perplexity、dev.to、Truth Social、Telegram、Trustpilot、Amazon、DripStack、本地语料和网页。v4 还把高赞评论、Polymarket 赔率变动和 Yahoo Finance 股价各压成一行，放在对应故事下面，方便直接引用。

`--store` 会把发现存进本地 SQLite 的 `research.db`，配合 `watchlist.py` 和 `briefing.py` 做定时监控和日报；`library feed` 和 `library search` 则把历史简报变成可订阅的本地 Atom 源和离线索引。

## 什么时候别用它

许可证是 MIT。README 声明无跟踪、无分析，默认全部在本机运行，数据只发往你启用的搜索 API。但有两个例外：配置了 `OPENAI_API_KEY` 等推理 key 时，话题和检索片段会发给该服务做相关性重排，不配 key 则回退本地打分；本地 SQLite 存储也只在显式开启 `LAST30DAYS_STORE=1` 时写入，且不会上传。

互动量高的内容未必正确，热度本身会放大情绪化或标题党内容，这是排序机制的代价。各来源的可用性取决于凭据、已装工具、话题和显式 opt-in，不是装完就全开。X 官方 API 走 `X_BEARER_TOKEN` 时，README 说默认只能取最近约一周的帖子，除非开发者项目有 full-archive 权限；浏览器登录态不受这个窗口限制，但账号风险更高。Claude Desktop 与 Claude Code 的 key 存储相互独立，同一组 key 要分别录入。

README 列出的成本包括 ScrapeCreators 前 10,000 次免费之后按量计费、Brave Search 每月 2,000 次免费、X API 额度来自你的开发者项目；YouTube、Bluesky 等免费。README 说它的定位是搜索真人，不是做事实核验；关键数字和结论仍应回到原始来源。编辑判断：用浏览器登录态或自己的 Reddit 账号去抓取，可能触发平台风控或账号限制，README 没有给出合规建议，使用前应自行确认平台条款。它也不适合需要审计级可复现性的正式研究，因为每次抓取结果会随平台数据变化。
