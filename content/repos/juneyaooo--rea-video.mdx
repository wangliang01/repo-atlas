## 它是什么

rea-video 做的是视频的逆向拆解：不生成相似视频，而是逐镜头判断画面是实拍、AI 生成还是代码与模板做出来的，再说明怎样重做。README 把目标写成「Reverse-engineer any video」，并按镜头给出结论。它覆盖实拍口播、桌面与手持产品演示、vlog、探店，AI 文生图与图生视频、AI 短剧、AI 音乐 MV，数字人头像，3D 与动画，代码动效、UI 演示、图表与幻灯片卡片，屏幕录制，以及混合剪辑；混合片会逐镜头判断后在原时间线上重组。

除视觉来源，每份拆解还整理字幕与样式文字的起止（可导出 SRT/ASS）以及颜色、描边、入场方式，贴纸、emoji 与画中画的位置和停留，剪辑点、节奏与是否踩拍，人声或 AI 配音、音乐来源与 BPM、音效落点，以及需要自己补拍的素材。它主要给能执行命令的 AI Agent 使用，README 点名 Claude Code 与 Codex；终端和 CLI 也能直接使用。

产出分两份：给人看的 `report.html` 或 PDF，结构更易读；给 Agent 的 VIDEO.md，是一种分层开放格式，模型只读当前问题需要的层。VIDEO.md 有独立的开放规范，其他 Agent 与工具即使不装 rea-video，也能按同一格式读取。对魔术类视频，它还会逐帧找出每个戏法的揭晓时刻并附慢动作片段，被要求时也提取反转、高潮和失误。和 Hypit 这类一键复刻工具相比，README 的 FAQ 说明差别在目的：rea-video 不渲染成片，先解释原片怎么做出来，再给拍摄方案、提示词或代码路径。编辑判断：它更像分析器加重拍规划器，而不是视频生成器。

## 怎么上手

README 给出的前置条件是 ffmpeg 与 Python 3.10+。最直接方式是在 Agent 里说一句话，让它安装并拆解：

```text
Install https://github.com/JuneYaooo/rea-video, then break down this video: /path/to/video.mp4
```

Agent 会安装 CLI、学习工作流并跑完。也可以装成 Agent 插件，插件只负责加入 skill，首次拆解时 Agent 仍会安装 CLI；README 说明 `.agents/plugins/marketplace.json` 是跨 Agent 的市场入口。命令如下：

```bash
# Codex
codex plugin marketplace add JuneYaooo/rea-video
codex plugin add rea-video@rea-video

# Claude Code
claude plugin marketplace add JuneYaooo/rea-video
claude plugin install rea-video@rea-video
```

不接视频模型也能用：工具离线分析原始文件，Agent 若能看图会自行复核不确定的镜头。README 说把 Gemini 或 Doubao 的端点与密钥交给 Agent，可让实拍、AI、3D 的判定更准，并为每个镜头补一条反推 prompt，费用由对应服务收取。输出目录含 `out/ref/VIDEO.md`，可用 `pip install videomd` 后执行 `videomd check out/ref` 校验；`rea-video prefs lang en` 切换英文报告。常见卡点是平台下载的视频经过二次压缩，会抹掉噪声证据，离线模式准确率随之下降；README 也说明仓库里的示例视频被重新压缩过，直接跑会得到与文中报告不同的结果。

## 值得注意的设计

README 把流程拆成四步。第一步切镜头，并把音轨分离成人声、音乐和音效；README 注明分离使用 UVR MDX-Net 与 BandIt v2，两个模型首次使用时下载，不在仓库内。第二步从三个通道取证：测量帧率、传感器噪声、整幅画面是否像一块平面移动、元数据里的 AIGC 标签；观察手部、文字和物理规律；听 BPM、调性与唱腔和说话的差别。第三步判定，硬证据优先于「看起来像」，冲突项标记出来交给 Agent 目视复核。第四步按目标视频模型的能力规划重拍，例如最大片段长度、是否支持多镜头、能接收几张参考图。

VIDEO.md 的核心设计是控制 token。README 说完整拆解可能达到数十万 token，因此格式分层：几百 token 的卡片、概览与地图、每镜头一行的时线，最后每镜头一个文件。每个文件标注自身大小，并把「屏幕上看到的」与「工具推断的」分开，Agent 只按问题展开。README 的案例可以说明这种分工：72 秒的实拍开箱在平台转码后，离线工具把 35% 的镜头判成 AI，Agent 复核后回到 97% 实拍；70 秒产品宣传片里 83% 是代码动效、12% 是录屏，因此不需要视频模型，一个 Remotion 工程即可重建。准确性表还显示，原片上仅用离线工具通常已足够；重编码过的平台视频需要视觉模型或 Agent 复核才能回到 99% 以上。重拍交给配套 capsule-cinema，默认按 MiniMax H3 规格生成；README 说明它会先做免费 dry run，确认后才调用付费模型。这种「先取证再生成」的分工是它和纯生成工具的核心差别，代价是流程更长、依赖 ffmpeg 与本地算力。

## 边界与风险

README 正文没有许可证章节，仓库采用什么授权需要到根目录另行确认，这是使用与二次分发前最需要补齐的信息；README 未说明商用条款、渲染耗时和最低硬件。BandIt v2 的权重标注为 CC BY-SA 4.0，模型本身不在仓库内，首次运行会联网下载，这一步的许可与网络安全需要自行评估。

准确性来自项目自己的评测集：README 公布调参集为 98.3%，留出集为 99.6% 与 98.9%，重编码微信视频为 88.6%；接入 Gemini 后重编码集升到 99.6%，再加 Agent 目视复核为 100%。这些是 README 的自测数字，README 未说明独立复现结果。自动重拍只完成一部分：AI 镜头可生成并放回原时间线，实拍镜头仍要按拍摄方案自己拍，代码镜头由 Agent 写成 Remotion 工程。它一次只处理一个视频，多集短剧要转到 rea-toon。README 的 FAQ 也提醒，只用离线工具可以避开模型费用，但能力受限于原片质量。能力表、评测结果和 Agent skill 目前是中文，英文只覆盖报告、CLI 帮助与消息。

合规上，README 明确要求不得直接搬运他人的画面、音乐、角色或肖像，发布时要遵守平台规则与当地的 AI 内容标注要求。README 还附声明：项目没有发行也不会发行加密货币代币，任何同名代币都与作者无关，提醒警惕诈骗。编辑判断：它适合想学习并复刻短视频结构、愿意接受人工复核与较长流程的人；不适合只想一键生成相似视频，或需要批量处理多集成片的团队。
