## 它是什么

agent-desktop 是 Vercel Labs 出的桌面 computer use 工具：不靠截图和像素匹配，而是读取操作系统给应用暴露的无障碍树，把可操作元素转成带 `ref` 的 JSON。Agent 对 `ref` 执行点击或输入，再读一次界面确认结果；观察—行动—验证—重试的循环留在调用方，它本身不含模型。

目标用户是写桌面自动化 Agent 的开发者，以及需要让 Agent 操作 Finder、Slack 这类原生应用的团队。交付形态有三类：CLI、C 库 `libagent_desktop_ffi`，以及可通过 stdio 暴露的 MCP 服务。README 把输出定义为一个 JSON envelope，成功与否、命令名和数据都在同一层，便于 Agent 统一解析。README 未说明对自绘界面的兜底方案，但提供了 `find`、`list-surfaces` 等命令，先帮 Agent 定位可操作的界面。README 说明 ref 只在本次快照内有效，调用方要自己保存并验证，工具不会替你记住历史。

## 它替掉了什么麻烦

它替掉的是「让 Agent 看截图、算坐标、再盲点」的桌面操作方式。README 没有回顾这类工具的历史，只给出差别：不需要截图，也不做像素匹配。编辑判断：截图加视觉模型把界面理解交给像素，分辨率、缩放和主题一变，坐标就可能失效；每次操作前后都要传图，token 和延迟也高。

agent-desktop 换成无障碍树：操作系统已经知道每个控件的角色、名称和可用动作，工具只负责序列化。和同类方案相比，README 未点名其他产品，也未给出对比数据。编辑判断：代价从「理解像素」变成「依赖应用是否把界面暴露给 AX、UI Automation 或 AT-SPI」，自绘界面可能只暴露很少节点。

## 跑起来要几步

最少两步：装好 CLI 并授权，然后对同一个界面做一次「快照—操作—再快照」的闭环。前置条件是 macOS 13+、Windows 10 1809+ 或 Ubuntu 24.04+，以及相应的辅助功能权限：

```bash
npm install -g agent-desktop
agent-desktop status
agent-desktop permissions --guide   # macOS 辅助功能授权
```

第一次跑通用 Finder：

```bash
agent-desktop snapshot --app Finder -i
agent-desktop click @s8f3k2p9:e8
agent-desktop snapshot --app Finder -i
```

每条命令输出一个 JSON envelope。`snapshot` 返回 `snapshot_id`、`ref_count` 和树；`ref` 形如 `@s8f3k2p9:e8`，前半段绑定这一次快照。执行后要用新的 `snapshot` 验证，而不是复用旧 `ref`。

常见卡点：只写 `@e8` 会被拒绝（`INVALID_ARGS`）；界面变化后旧 `ref` 会得到 `STALE_REF` 或 `AMBIGUOUS_TARGET`；多窗口时先用 `--window-id` 指定；密集应用先跑 `snapshot --skeleton --app Slack -i --compact` 再下钻；PowerShell 里每个 `ref` 要加引号，因为裸 `@token` 是 splatting 操作符。默认 headless，不移动指针、不抢焦点，需要真实输入时加 `--headed`。README 还说 macOS 和 Linux 可用 `brew install agent-desktop`，官方没有 Scoop 包；直接执行原生包时要把 helper 放在可执行文件旁边。

安装也可以用 Bun、Yarn、pnpm；包内带 x64 和 ARM64 的原生二进制与平台辅助程序。完成 macOS 辅助功能授权后，`status` 会显示平台、权限和当前可用的 surface。README 未给出安装包体积或首次启动耗时。

## 它把复杂度放在哪

复杂度放在「快照加 ref」这个抽象和平台适配层上。ref 只在所属快照内有效，UI 一变就失效，这逼着 Agent 重新观察，避免在过期坐标上盲操作。错误码也服务于这个循环：`STALE_REF` 表示重新快照，`AMBIGUOUS_TARGET` 表示目标不唯一；只有当 `error.disposition.retry` 为 `safe` 时才建议重试。

架构上，CLI 和 C 库走同一个 core，再通过 `PlatformAdapter` 接口落到编译期选定的平台 crate：macOS 用 AX API，Windows 用 UI Automation，Linux 用 AT-SPI。因此每个二进制只针对一个 OS 构建，跨平台支持靠分别构建，而不是运行时探测。C 库适合在自己的进程里调用，README 给了 Python `ctypes` 示例，初始化时要校验 `AD_ABI_VERSION_MAJOR`。

对 Agent 友好是另一条设计线：二进制内置与版本匹配的说明，`agent-desktop skills get desktop` 讲循环和重试规则，`skills get platform` 讲平台差异，还可以把 skill 装进 Claude Code、Cursor 等 harness。`agent-desktop mcp` 把每条命令映射成 `desktop_snapshot`、`desktop_click` 这样的 MCP 工具，返回同样的 envelope。

命令面很宽：README 说有 61 个命令名、57 个可操作命令。命令按组覆盖观察（`snapshot`、`find`、`get`、`is`、`screenshot`、`list-surfaces`）、ref 操作、键鼠、应用与窗口、通知、剪贴板、等待、会话、沙箱和系统信息。`key-down` 等四个命令在守护进程能释放按键或按钮前会拒绝执行，这是为了防止按键卡住。`batch` 可一次执行多条命令，但 README 提醒批量 JSON 里的文本会出现在进程参数中，不适合放密钥；`type`、`set-value` 和 `clipboard-set` 接受 `--stdin`，让敏感文本不进参数。`sandbox exec` 的 guest 命令有自己的参数，`mcp` 的全局 flag 不作用于它。README 还提供 `CONCEPTS.md` 统一 ref、surface、session 等词，避免 Agent 和人对同一个词理解不同。代价是工具面越大，调用方越需要靠 skill 和错误码来约束行为。

## 什么时候别用它

把 `click`/`type` 直接交给自主 Agent、又需要强安全边界的场景，不适合它。许可证是 Apache-2.0。平台限制是硬性的：macOS 13+、Windows 10 1809+、Ubuntu 24.04+；每个平台能 headless 做什么、什么必须 `--headed`、什么直接拒绝，要看对应平台页，README 没有汇总成一张表。

隐私风险 README 主动写明：快照、剪贴板读取、截图、命令输出和调试产物都可能含桌面私密内容，不要进公开日志或上传。它默认不移动鼠标、不抢焦点，但这只是交互方式，不是权限隔离；Agent 仍能读到当前桌面能读到的内容。

安全边界 README 未说明：没有提到操作确认、审计日志、命令白名单或沙箱逃逸模型。编辑判断：把 `click`/`type` 直接暴露给自主 Agent 前，应在测试账号和低权限环境里跑，并对删除、发送、支付类操作加人工确认。

适用性取决于应用的无障碍实现。自绘 UI、游戏、部分 Electron 或 Canvas 应用可能只暴露很少节点，这类场景仍要回退到截图或专用 API。README 未说明对这类应用的成功率或兜底策略，也没有给出各平台无障碍树的节点上限或快照大小；超大窗口通常要靠 skeleton 和局部下钻控制。README 未说明操作是否会上报遥测，也未给出整体成功率数据；它对 macOS、Windows、Linux 分别构建，跨平台部署要按目标系统各装一份。README 未说明对高 DPI 或多显示器混用的处理方式，也未说明超大桌面下快照如何裁剪。
