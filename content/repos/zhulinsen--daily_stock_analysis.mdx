## 它是什么

daily_stock_analysis 是一套 LLM 驱动的多市场股票分析流水线。它每天读取自选股的行情、K 线、技术指标、新闻、公告和基本面，生成一份“决策仪表盘”，包含核心结论、评分、趋势、买卖点位、风险警报、催化因素和操作检查清单，再推送到企业微信、飞书、Telegram、Discord、Slack 或邮箱。

覆盖市场是 A股、港股、美股、日股、韩股、台股和 ETF。使用者是有跨市场自选股、希望每天定时收到统一摘要的个人投资者，以及想把这套流程部署成服务或插件的开发者。

报告的字段是固定的。README 的样例包含买入、观望、卖出的数量，逐股评分与多空判断，以及舆情情绪、业绩预期、风险点、利好催化和最新动态；另有大盘复盘模板，列主要指数、涨跌家数、涨停跌停和领涨领跌板块。

它和行情 App 的差别在于“聚合 + LLM 归纳 + 推送”：数据源可替换，报告结构统一，输出能进群机器人；和交易系统相比，README 没有提到下单或券商接口，定位是分析与提醒，不是自动交易。

## 怎么上手

README 推荐 GitHub Actions，零服务器、约 5 分钟完成：

1. Fork 仓库。
2. 在 `Settings → Secrets and variables → Actions` 配置 Secrets：至少一个 LLM Key（如 `MODELFLARE_KEY`、`GEMINI_API_KEY`、`OPENAI_API_KEY`），至少一个通知渠道，必填 `STOCK_LIST`（如 `600519,hk00700,AAPL,7203.T,005930.KS,2330.TW`），建议再配一个新闻搜索 Key。
3. 在 Actions 页启用 workflows。
4. 手动跑一次“每日股票分析”，确认收到推送。

默认每个工作日北京时间 18:00 执行，非交易日（含 A/H/US 节假日）不跑。

本地运行：

```bash
git clone https://github.com/ZhuLinsen/daily_stock_analysis.git && cd daily_stock_analysis
pip install -r requirements.txt
cp .env.example .env && vim .env
python main.py
```

常用参数有 `--debug`、`--dry-run`、`--stocks`、`--market-review`、`--schedule`、`--serve-only`；Web 工作台用 `python main.py --webui` 启动，访问 `http://127.0.0.1:8000`。部署形态包括 Docker、FastAPI 服务和桌面客户端打包。

常见卡点：免费行情源会限流或接口变动，日志里的“未配置”不影响运行但会影响稳定性；GitHub Actions 里不适合跑 Ollama，推荐云端 API；Windows 源码安装要用短路径（如 `C:\dsa`），否则可能遇到依赖路径过长。

## 值得注意的设计

它把数据源做成按市场可替换的层。行情默认用 AkShare、Baostock、YFinance 等免费源，零配置可跑；要稳定就换 TickPlus、Tushare、Longbridge 等 token 型源。新闻搜索接 SerpAPI、Tavily、博查、Brave、MiniMax、SearXNG。README 说新闻源会显著影响舆情、公告、事件和催化因素的质量，建议至少配置一个；完整指南里还有 fallback 优先级规则，说明单一源失败时会降级。

LLM 也是可替换的：Gemini、OpenAI 兼容、DeepSeek、通义千问、Claude、Ollama 本地模型，以及 README 赞助位里的聚合服务。模型只负责把聚合后的数据写成报告，不直接下单；这种分层让“取数失败”和“模型判断错”可以分开排查。

输入侧支持图片、CSV/Excel、剪贴板和股票代码/名称/拼音/别名补全；问股支持均线、缠论、波浪、趋势、热点、事件、成长、预期等 15 种内置策略，可在 Web、Bot 和 API 里用，也支持多轮追问和自定义策略文件。

输出侧做了多通道适配：企业微信、飞书、Telegram、Discord、Slack、邮件都有对应的 Secret 配置，README 还给了决策仪表盘和大盘复盘的实际样例。Web 工作台把手动分析、任务进度、历史报告、回测、持仓、配置管理放在一起，适合不想只看群消息的人。

Agent 集成是另一条产品线：仓库提供 `plugin/` 和 `.agents/plugins/marketplace.json`，`stock_analyzer` 技能驱动一个已部署的 DSA 检出或正在运行的服务，不自带 `src/` 运行时；还有只读 MCP 服务 `python -m src.mcp_server`。编辑判断：作者把 DSA 当成“可被别的 Agent 调用的分析后端”，而不只是一个定时脚本。

## 边界与风险

许可证是 MIT。README 有明确的免责声明：仅供学习和研究，不构成投资建议，作者不对损失负责。编辑判断：这句话不是客套，LLM 可能读错新闻、算错指标或在缺失数据时编出结论，任何买卖点位都应回到原始行情核对。README 还给了一篇 arXiv 论文链接，但正文没有复述论文结论或回测指标。

数据风险来自免费源。README 自己说 AkShare、Baostock、YFinance 受上游限流、接口变动和网络波动影响，稳定性不保证；长期定时、批量分析建议用 token 型数据源。数据源的授权条款、调用配额和商用许可要自己确认。

成本和安全：GitHub Actions 托管本身可以零成本，但 LLM API Key、搜索 API、行情 token 和推送渠道可能收费；把 Key 放在仓库 Secrets 里是标准做法，但 fork 后的 workflow 权限、日志脱敏和第三方 Action 仍需检查。从数据流看，自选股、持仓和报告会发给模型服务商与推送平台，README 未说明数据保留和隐私策略。

不适合谁：需要实时交易、自动下单或券商级风控的人；需要持牌投资顾问合规输出的机构；以及不愿维护 API Key 和数据源变化的人。编辑判断：它更适合当信息聚合、每日复盘和提醒工具，而不是决策的唯一依据。
