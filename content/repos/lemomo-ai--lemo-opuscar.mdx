## 它是什么

Lemo-Opuscar 不是视频生成模型，也不是素材站，而是一套给编码 Agent 的影片风格库。它提供 99 种风格，按画面分成 15 类，从剪辑纪录片、水彩插画、白板讲解到 3D 微缩和数据地图；每种风格都有样片、剧照，以及 Agent 需要遵循的 `STYLE.md`。用户只要选一种风格并给出主题，Agent 就会自己写 canvas/WebGL 页面、逐帧渲染、用免费采样库作曲、用文本转语音配音，最后混成短片，全程不使用视频生成或现成素材。

它给谁用？README 明确说项目「为 Claude 构建」，主要面向使用 Claude Code 的创作者；Claude Fable、Opus 和 Sonnet 都能用，最好把 effort 设为 high，其他模型「可能无法还原这些风格」。和同类方案的差别在于产出路径：不是让模型生成像素，而是让模型写代码来画，所以风格可以像代码一样复制、改写和版本管理。由哪些部分组成：`DIRECTOR.md`、`TECHNIQUE.md`、每种风格的 `STYLE.md`、可复用的 `core/` 工具，以及把风格做成自己版本的流程。

## 怎么上手

推荐方式是把这个仓库当作 Claude Code 的插件市场安装：

```sh
claude plugin marketplace add lemomo-ai/lemo-opuscar
claude plugin install lemo-opuscar@lemolab
```

首次使用会把指南、工具和风格提示词下载到 `~/lemo-opuscar`，之后所有影片共用；每支影片的项目则留在启动命令时所在的文件夹。也可以直接克隆仓库，影片会写进 `films/<name>/`：

```sh
git clone https://github.com/lemomo-ai/lemo-opuscar.git
cd lemo-opuscar
claude
```

其他支持 skills 的 Agent 可以把 `plugin/skills/lemo-opuscar/` 复制到自己的 skills 目录。README 另提供简体中文说明，线上画廊也有中文版。运行前需要 Node 20+、ffmpeg 7+ 和 Python 3.11+（或 uv），其余依赖由 Agent 安装；README 特别提醒 Ubuntu 24.04 自带的 ffmpeg 6.1 太旧，要用静态构建。更新命令是 `claude plugin marketplace update lemolab && claude plugin update lemo-opuscar@lemolab`，第三方市场默认不自动更新，要到 `/plugin` 里手动打开。首跑预期看到的是 Agent 先问清主题里无法决定的部分、是否自带语音或音乐、要不要先看故事板，然后才开始制作。

README 估计一支影片需要 Agent 工作 30 到 60 分钟，并消耗不少 token；默认输出 1920x1080、24 fps，部分风格会改成 30 fps。Manga Panels、Text Flash Cuts、Comic History Cartoon 这三种风格还需要用户自备图像生成器，例如登录后能生成图片的 Codex CLI，否则无法启动，其余风格不依赖它。常见卡点是 ffmpeg 版本和外部图像生成能力，README 都给出了对应说明。卸载时用 `claude plugin uninstall lemo-opuscar@lemolab`，再删除 `~/lemo-opuscar`；`~/lemo-my-styles/` 里的自有风格会保留。从克隆路径使用时，更新要先 `git pull`，再跑一次 `sh plugin/skills/lemo-opuscar/scripts/setup.sh deps`。

## 值得注意的设计

第一层是把「导演」和「技术」拆成三份文档。`DIRECTOR.md` 负责故事、声音、节奏、镜头、表演和自查；`TECHNIQUE.md` 负责逐帧渲染、语音、音乐与混音；`styles/<style>/STYLE.md` 只描述这种风格看起来和听起来是什么样，故事仍由用户提供。Agent 读这三份文件后按「小工作室」的方式工作，先问清主题里无法决定的部分、是否自带语音或音乐、要不要先看故事板，然后才开始制作。

第二层是完全基于代码的渲染链。画面由 canvas 和 WebGL 页面逐帧绘制，音乐来自免费采样库，旁白用文本转语音，最后混音输出；没有视频生成，也没有 stock footage。这个选择让风格可以像代码一样被复制、改写和版本管理，但也意味着画面复杂度受绘制代码限制，README 没有给出渲染性能基准。

第三层是「把风格变成自己的」流程。用户可以改一种库内风格，也可以从空白页描述一种新风格。系统会把库内风格拆成「可以安全修改」（配色、字体、节奏、声音、标志性动作）、「会改变性格」（材质与渲染、色彩逻辑、镜头语法）和「不能改」（风格本质）三类，每一轮最多改五处；修改前先给前后对照和代价，再用真实代码渲染一帧与原始风格并排比较，确认后生成 15 到 30 秒的样片，最后保存在 `~/lemo-my-styles/<name>/`。这个目录不会被库更新或卸载覆盖，之后按名字就能调用自己的风格。

风格库本身也是内容的一部分：99 种风格按画面分成 15 类，站点上每种风格都有样片、剧照和可复制的句子。README 记录了 2.0.0 把风格库更新为 Claude Fable 5.2 并改用 CC BY-NC 4.0 的原因——风格库曾被重新打包进付费产品，所以文档改为非商业许可，代码仍是 MIT。第三方贡献的 Memphis Diorama 和 Crayon World 3D 按作者书面许可使用，需要同时署名。

## 边界与风险

最需要先看清的是许可，而不是功能。代码（`core/`、`tools/`、`styleboard/`、`plugin/` 脚本和各 demo 的代码）是 MIT；所有 Markdown 文档和图像生成提示词是 CC BY-NC 4.0，只允许非商业分享和改编。README 额外给了一条授权：用户及其合作方（员工、外包、客户）可以阅读、复制和改编这些文档来制作自己的影片，包括商业片和客户片，并可把改编版本放进该影片的交付文件；但不能把文档或其改编版分享给这之外的人或出售。任何其他商业用途，例如把风格库整体或部分放进付费产品或服务，需要单独的商业许可。demo 影片、海报、剧照和字幕是 CC BY 4.0；六条旁白因使用 Edge TTS 或豆包 TTS 被明确排除，不得提取复用；字体、Poly Haven 模型和采样库各按自己的许可。用这个库做出的影片归用户所有，商业片也不需要署名。

运行层面的限制也来自 README：项目明确「为 Claude 构建」，换模型可能复现不好；ffmpeg 版本要求较新；单支片子耗时以小时计并消耗大量 token；三种风格依赖外部图像生成能力。README 没有给出 GPU 要求、自动化测试套件或渲染性能基准，也没有说明非 Claude 模型的兼容矩阵，这些都属于未说明的部分。

编辑判断：对于需要稳定、可审计产线的团队，建议先用它做一支样片，确认风格质量、许可路径和成本，再决定是否纳入正式流程；把风格库直接嵌入付费产品则要先取得商业许可。
