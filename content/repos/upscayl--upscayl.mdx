## 它是什么

Upscayl 是一款本地运行的 AI 图片放大工具。它用 Real-ESRGAN 一类模型把低分辨率图片放大，并按模型「猜」出缺失的细节，目标是放大后尽量不掉画质。README 把它定位为免费、开源的跨平台桌面应用，覆盖 Linux、macOS 和 Windows，顶部标注的当前版本是 v2.15，下载和文档都指向 upscayl.org 与 GitHub Releases。

它面向需要在本地批量处理图片的人：摄影爱好者、整理设计素材的人、修复老图的人。和只在命令行里跑的 `upscayl-ncnn` 相比，Upscayl 多了图形界面、批量队列和模型选择；和在线放大服务相比，它把计算放在本机 GPU 上。README 还给出三条安装路径之外的辅助入口：文档、更多模型仓库、模型转换 Wiki、兼容性列表和排错页。

核心分成三层：桌面应用外壳、内置的放大模型，以及独立的 `upscayl-ncnn` 推理后端。模型来自 Real-ESRGAN 研究和社区作者；README 致谢里点名了 High Fidelity（HFA2k）、Remacri、Ultrasharp 和 Ultramix Balanced。README 称后端完全开源、采用 AGPLv3；仓库元数据同样标为 AGPL-3.0。

## 它替掉了什么麻烦

在它之前，放大低分辨率图片主要靠图像软件插值、在线放大服务或命令行推理后端，痛点是前两者要么不生成细节、要么要把原图传出去，后者又缺少图形界面和批量队列。README 未说明这段历史，也没有给出与替代方案的定量对比；这是编辑判断，依据是 README 的 FAQ、安装说明和 CLI 指向。

三条替代的具体形态是：图像软件插值不生成细节；在线服务让原图离开本机；`upscayl-ncnn` 要自己准备环境和命令，没有批量队列与图形界面。README 说 Upscayl 用 Real-ESRGAN 和 Vulkan 架构在本机推理，模型负责「猜」细节。差别因此落在两点：一是把命令行推理包成可安装的桌面产品，二是把计算留在本机。编辑判断：对怕上传素材或要一次处理几十张图的人，这两点比算法新旧更重要；代价是 README 明确要求一块 Vulkan 兼容 GPU，多数核显和纯 CPU 环境跑不起来。这三条替代路线各自的历史与优缺点，README 均未说明。

## 跑起来要几步

前置条件是兼容 Vulkan 的 GPU。README 说明多数核显和纯 CPU 环境跑不起来，但建议先试；社区还在 issue #390 提供了 Windows/Linux 的绕行方案，macOS 与 Haiku 上没有对应办法。

安装按平台走：

- Linux：Flatpak、AppImage、AUR、Snap 或 ebuild；AppImage 需要在右键菜单的属性里勾选允许执行。多数发行版的应用商店也能装 Flatpak 或 Snap 版。
- macOS 12+：下载 dmg 拖进 Applications，首次右键「打开」；也可以 `brew install --cask upscayl`。
- Windows 10+：下载 exe 安装，遇到 SmartScreen 选「更多信息」再「仍要运行」。

Linux 除 AppImage 外还提供 RPM、DEB 和 ZIP；遇到兼容性问题可查 Wiki 的 Compatibility List 和 Troubleshooting，命令行用户则可以直接用 `upscayl-ncnn`。

README 没有给出首次运行的完整界面步骤，只把教程指向 `docs.upscayl.org`。按它的描述，选择图片和模型后开始放大。批量任务如果中途取消，README 提醒要等所有图片先完成放大再做后处理，否则可能出现未压缩或尺寸不对的结果。模型不够用时，可以从 `upscayl/custom-models` 取更多模型，或按 Wiki 的模型转换说明自己转。

常见卡点有三个：没有 Vulkan 显卡；Windows 没开性能模式，导致 GPU ID 的选择被系统覆盖；把失焦照片误当成低分辨率来救。README 明确说它不能去模糊或调整焦点，遇到这类图应改用别的工具。

## 它把复杂度放在哪

复杂度主要落在推理后端和模型选择上，而不是界面。编辑判断：Upscayl 的价值不在算法原创，而在把 Real-ESRGAN 加 NCNN Vulkan 的本地推理封装成可安装的桌面产品。README 的 FAQ 说模型是「猜」出细节，这也解释了它的适用边界：像素化、低分辨率图能救，失焦图救不了。

模型可替换是另一个关键设计。README 的致谢列出了 High Fidelity、Remacri、Ultrasharp 和 Ultramix Balanced 等社区模型，同时提供自定义模型目录和转换流程，让用户按不同模型的特点换用。代价是模型与后处理能力并不一一对应：README 提到某些模型不支持某个动作时，程序会先放大完所有图片再统一后处理，所以批量任务不能按单张即时完成。

GPU 选择通过 GPU ID 暴露给用户，多显卡机器可以指定；Windows 上如果电源计划不是性能模式，系统可能覆盖这个选择。这个细节说明它把性能调优交给用户，而不是自动探测。README 的路线图也只写了两件事：修 bug，以及让更多人用上 FOSS，没有承诺具体功能时间表。

隐私方面，README 没有直接写「图片不上传」。但从安装方式、Vulkan 本地推理和 FAQ 的硬件要求看，README 描述的是在本机完成推理，它也没有提供云端接口。编辑判断：这正是它相对在线服务的核心卖点，但不要把「没有提到上传」当成经过审计的隐私承诺。

## 什么时候别用它

许可证是 AGPL-3.0。README 只强调了后端 `upscayl-ncnn` 的 AGPLv3；如果你修改后通过网络提供服务，AGPL 的源码开放义务需要自行确认。内置和自定义模型各自的许可证，README 未说明。

硬件门槛是硬限制：需要 Vulkan 兼容 GPU，很多核显不可用，macOS 需要 12+，Windows 需要 10+。README 未说明最低显存、单张耗时和支持的图片格式，也没有给出速度基准或与商业工具的对比数据。

效果风险来自「生成细节」。README 建议对照 `COMPARISONS.MD` 的示例图判断适用性，而不是拿完全模糊的照片测试。模型补出来的是猜测，不是原始信息；人像、文字、证件类图片要逐张检查，不能当作证据修复。它也不能去模糊或做焦点校正。README 也未说明遥测、崩溃上报或更新检查会发送哪些数据。

编辑判断：Upscayl 适合有独立显卡、追求免费本地批量放大的用户；没有 Vulkan 显卡、需要修复失焦照片，或要在服务器上无头运行的人，应改看 CLI 后端或其他方案。它也不适合需要可复现的批量流水线和精确计时的生产环境，README 没有给出这方面的任何保证。
