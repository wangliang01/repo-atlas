## 它是什么

Agent Reach 是给 Agent 补互联网入口的本地工具。Claude Code、Codex、Hermes Agent、OpenClaw 这类 CLI 自带网页搜索，但 README 列出四类它们基本够不着的东西：要登录才能用的功能（小红书搜笔记、X 查账号动态）、视频里的内容（B 站和 YouTube 字幕、播客转写）、中文平台（B 站、小红书、V2EX、雪球），以及干净的结构化数据（雪球行情、V2EX 帖子和回复、GitHub 仓库和 issue）。

它把这些平台背后的工具替你装好、测好，Agent 用一条命令调用。支持 14 个渠道，分三级：默认渠道装好即用，包括 B 站、V2EX、GitHub、YouTube 和网页；可选渠道要你说一句「加上小红书」才开启；实验渠道能用，但 README 明说平台反爬更严、可能随时失效。

## 它替掉了什么麻烦

它替掉的是「Agent 自带搜索够不到登录墙和中文平台」这件事。README 直接点名四类缺口：登录功能、视频里的字幕和语音、中文平台、结构化数据；编辑判断：没有它时，Agent 要么只能读公开网页，要么让用户手工复制帖子、字幕或行情，再贴回对话，链路断在人的环节。

README 说自己把这些平台背后的工具装好、测好，Agent 一条命令就能用，例子里 `agent-reach channels` 看渠道、`agent-reach bilibili search "大模型"` 搜内容、`agent-reach read <链接>` 按链接自动选渠道。编辑判断：这把「每个平台怎么调」的知识从用户或提示词里挪进工具，Agent 不需要记每个站点的接口。

和单纯给 Agent 一个搜索 API 的差别是，它按平台组织动作，并处理登录、字幕、语音转写这些具体环节。README 还在致谢里列出 OpenCLI、bili-cli、boss-agent-cli、yt-dlp、Jina Reader、Exa，说明它是把多个上游工具编排起来，而不是自建所有抓取。README 未给出与其它搜索 API 或浏览器的横向性能对比。

## 跑起来要几步

最省事的安装方式是把这句话发给 Agent：

```
帮我安装 Agent Reach：https://raw.githubusercontent.com/Panniantong/Agent-Reach/main/docs/install.md
```

安装和升级都用同一条 GitHub 地址。前置条件是 uv，README 说它会自动安装且不需要管理员密码；Python 要求 3.10+。过程中 Agent 可能会问你三件事：是否允许执行命令、是否安装 uv、要不要加可选渠道。装完后默认能用的就是上面五个渠道，预期可以用下面的命令验证：

```bash
agent-reach channels                          # 有哪些渠道、每个渠道能做什么
agent-reach bilibili search "大模型"           # agent-reach <渠道> <动作> [参数]
agent-reach read https://www.v2ex.com/t/123   # 按链接自动选渠道
```

常见卡点：README 特别提醒 PyPI 上叫 `agent-reach` 的包不是本项目，只能按 install.md 里的 GitHub 地址装；有时 Agent 说自己不能运行命令，要去它的设置里开启命令执行；YouTube 语音转文字和播客转写要 Groq 或 OpenAI Key，Key 应在自己的终端里用 `agent-reach configure groq-key` 填写，不要发在聊天里；小红书、X、Reddit 等需要登录，登录过期时要重新走一次专用登录窗口。

所有安装内容集中在 `~/.agent-reach/`，升级、换账号、卸载都可以用大白话让 Agent 做，比如「看看 Agent Reach 状态」「去掉小红书」「卸载 Agent Reach」。

## 它把复杂度放在哪

复杂度放在「每个平台的每个动作对应一个按顺序尝试的工具列表」，而不是一个绑定死的脚本。比如读 B 站视频先用 bili-cli，失败自动换 B 站公开接口；读网页先用 Jina Reader，再用 Exa。README 的理由是平台改版、工具失效是常态，换工具只需要调整列表，Agent 的调用方式不变。编辑判断：这个设计把易碎的抓取细节收进配置层，确实比让 Agent 自己记每个平台怎么调更稳，但也意味着某个动作的最终质量取决于列表里最后一个还能用的工具。

登录模型是另一处设计取舍。需要登录的平台使用 Agent Reach 自己的专用浏览器，在后台运行、不弹窗，只对本机开放。第一次用某个网站时，它会把你 Chrome 里这个网站的登录复制一份过去，原浏览器不变，也不读密码库。README 明确说 Agent 从不替你登录、不要密码；确实需要重新登录时才打开窗口由你本人完成。专用浏览器和集中目录让清理变得简单，但复制的通常是主账号，README 因此建议换成小号。

渠道分级是维护边界的显式表达：默认渠道承诺可用，可选渠道按需安装，实验渠道提前告知可能失效。README 还写明默认渠道「不想要也可以去掉，以后更新不会再加回来」。编辑判断：这比很多项目把所有平台都标成「支持」更诚实。只读也是设计约束：只搜索和读取，不发帖、不评论、不点赞、不私信。编辑判断：这只减少了写操作带来的风险，不代表平台允许自动读取。

## 什么时候别用它

要求审计、合规授权或稳定数据管道的团队，不适合用它。许可证是 MIT。README 的安全声明包括：只读、不替你登录、不要密码、专用浏览器只对本机开放、建议用小号、Key 不要发在聊天里。这些是项目声明，不等于平台认可这种访问方式。编辑判断：复制浏览器登录态并自动访问，仍可能违反平台条款或触发风控，账号被限制的风险由使用者承担；README 建议小号正是对这个风险的承认。

能力依赖要逐项看：B 站字幕、小红书、雪球热帖、Boss、Reddit、X 等需要登录；YouTube 转写和小宇宙转写需要 Groq 或 OpenAI Key；LinkedIn 公开职位不用登录，站内搜索要登录。实验渠道（X、Facebook、Instagram）随时可能失效，README 未给出修复时限或 SLA。它也不保证内容真实、完整或合规，Agent 读到的帖子、评论和行情仍需自己核对。

运维上，所有东西集中在 `~/.agent-reach/`，卸载只删自己装的内容，这是加分项；但多个 Agent 共用同一套登录和渠道状态，一个渠道坏掉会影响所有使用者。README 未说明并发访问、频率限制或缓存策略。适合需要给 Agent 快速补齐中文平台和登录内容的个人开发者；不适合要求审计、合规授权或稳定数据管道的团队。
