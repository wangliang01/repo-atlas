## 它是什么

CleanYourTV 不是应用商店里的成品 App，而是一套给 Android TV 与 Google TV 用的去广告、去预装工具集。它利用电视自带的调试桥，先备份已安装包与设置，再用 `pm disable-user` 停用厂商遥测、广告服务、内容推荐行和预装杂项，最后安装一个原生启动器并设为默认桌面。README 的核心承诺是：不需要 root，不需要拆机接线，不卸载任何东西，改主意时有一条命令恢复。

它面向愿意在电脑上动手的电视用户，也照顾不写代码的人。仓库提供一段写给编码助手的 PROMPT.md，助手会自行发现电视上的预装项、逐步征求确认、构建并安装启动器。没有编码助手时，同一套脚本可以手动运行；没有电脑时，README 列出了几个由独立开发者基于这些电视清单构建的社区 App。README 明确说官方入口只有 cleanyour.tv 和这个仓库。

换上的桌面是这个项目的一半卖点。README 描述的效果包括：纯黑背景和圆角 dock，放四个常用应用；顶部 shelf 用大字显示当前聚焦的应用，并从封面取色做环境光；按向下键滑出其余应用的网格；三个磨砂按钮打开输入源、网络和设置；还有问候语、细时钟和日期。它没有赞助行、没有 Discover 推荐、没有回传分析。

## 它替掉了什么麻烦

它替掉的是「进设置里逐个停用应用，或者装一个通用去广告 App」的做法。README 没有评测这些旧做法的效果；它在 The story 里交代了项目的来路：作者 2026 年 10 月发了一组父母电视前后对比，很多人照着做，回复最后变成了仓库里的机型清单。

编辑判断：手动关应用的痛点是每台电视的预装不同，包名要自己找；通用 App 未必有针对你机型的清单，也可能没有可回放的恢复记录；而且这些做法都不换桌面，首页的推荐行仍在。CleanYourTV 把三件事合起来：按机型维护的清单、执行前的状态记录与恢复脚本，以及一个替换启动器。

README 称清单已覆盖 508 个电视型号、139 个品牌；编辑判断：这些数字说明社区贡献很活跃，但具体机型是否可用仍取决于对应清单的测试质量。

## 跑起来要几步

三步：开调试、把仓库和 PROMPT.md 交给编码助手、按电视上的提示确认。电脑需要与电视处于同一 Wi-Fi，并且有 shell、Python 3、17 到 22 之间的完整 JDK，以及 Android SDK platform 34 和 build-tools 34。电视端在设置里连按 Build 七次打开开发者选项，再启用 USB debugging。

装好前置条件后，可以按 README 的手动流程执行：

```bash
python3 -m venv tools/venv && tools/venv/bin/pip install -r tools/requirements.txt
export TV_HOST=192.168.1.50

tools/venv/bin/python -I tools/tv.py --probe
tools/disable.sh examples/xiaomi-mi-tv-4a/debloat.txt
tools/restore.sh examples/xiaomi-mi-tv-4a/debloat.txt
launcher/build-and-install.sh
```

`TV_HOST` 换成电视的实际 IP。`--probe` 会读型号、Android 版本和固件；`check.py` 用来对比固件更新后哪些包被带回来了，加 `--fix` 会重新停用。更省事的方式是克隆仓库后把 PROMPT.md 粘给 Claude Code、Codex、Gemini CLI 等助手，并填入电视型号，由它完成备份、清理、构建、安装和截图核对，README 称大约十五分钟。电视上会出现「Allow USB debugging?」，接受后还要回答一份清单：哪些应用在用、dock 大小和应用顺序、是否保留语音助手、Chromecast 和更新。

Windows 下每个脚本都有对应的 PowerShell 版本。没有电脑的人可以用社区 App，README 说它们各自独立、按自己的许可证提供，不属于 CleanYourTV。

常见卡点有三个。macOS 可能报 No route to host，原因是本地网络隐私权限属于终端 App，需要在系统设置里允许并重启。其次，必须等新启动器装好并运行后再停用原厂桌面，否则 Home 可能落到工厂测试应用上。第三，Google TV 的 setupwraith 可能抢走 Home 并导致系统崩溃循环，停用前要先用 `dumpsys wifi` 确认 Wi-Fi 网络不是它保存的。

## 它把复杂度放在哪

复杂度放在「只禁用、不卸载」和 Home 守卫上。所有改动都通过 Android 自带的 `pm disable-user` 完成，等价于设置里的停用应用。执行前脚本会把电视当时的状态记录到 `~/.cleanyourtv/`，`tools/restore.sh` 再按记录回放，原本就被用户停用的包不会被误启用，Home 也会回到原来的组件。恢复后启动器仍留在电视上，需要的话要手动删除。

Home 守卫是第二层。脚本只停用自己认识的五个原厂启动器，并在清单包含当前 Home 所有者、且没有其他应用能响应 HOME 时跳过该条目。在 Google TV 上还要处理 setupwraith 抢走 Home 的情况。设置向导、设置应用、厂商的 FallbackHome 和工厂测试应用也会响应 HOME，但不算数。

第三层是极简启动器本身。它用纯 Java 编写，约 572 KB，面向 1 GB 内存的电视，没有模糊、视频、网络权限或后台服务，最低支持 Android 8.0。桌面布局、壁纸和主题由一份 `config.json` 通过 Wi-Fi 推送，不需要重新构建；仓库自带 33 个主题，支持 31 种语言和希伯来语的完整 RTL 镜像。

工具链也值得一看。纯 Python 的 ADB 客户端 `tools/tv.py` 在原厂 adb 被拦截时仍能执行 shell、推送、拉取和截图；`tools/relay.py` 给进不了局域网的助手转发端口；`tools/privacy.py` 审计语音、ACR 和遥测候选并输出证据；`tools/adb-closed.py` 确认调试关闭后 5555 端口确实不可达。

## 什么时候别用它

支持范围写得很清楚：只适用于 Android TV 和 Google TV。Fire TV 只能做去预装那一半，因为 Fire OS 不会把 Home 交给第三方启动器，2015 年的 Fire TV Box 连这一半也会失败。部分中国市场的 TCL 机型拒绝安装任何启动器。Samsung Tizen、LG webOS、Roku、Vizio 和 Hisense VIDAA 没有 ADB，完全不在支持范围。

风险主要在 ADB 与系统包两点。网络 ADB 在 5555 端口上是明文传输，某些固件下局域网内任何设备都能拿到 shell，因此用完后必须关闭调试、撤销授权、重启电视，并用 `tools/adb-closed.py` 确认端口已关闭。停错系统包可能让电视功能异常，所以清单要小批量应用并随时准备恢复；最坏情况下可以进恢复菜单做恢复出厂设置。固件更新会把停用的包带回来，需要用 `tools/check.py` 对比并按需修复。README 也没有对保修作承诺，只提醒修改电视软件可能影响保修或支持。

仓库不提供预编译 APK，需要自己用脚本构建。项目采用 MIT 许可证，内置字体使用 SIL Open Font License。README 的 Legal 章节强调它只使用电视向所有者开放的设置，不 root、不刷固件、不绕过锁或 DRM。隐私方面，README 提到可以用 Android 的 Private DNS 配合广告拦截解析器，但该解析器会看到电视的全部 DNS 查询，而且不能去掉 YouTube 内的广告。README 未说明具体机型在长期使用中的稳定性；编辑判断：先在次要电视上验证恢复流程，再处理主力设备，是更稳妥的顺序。
