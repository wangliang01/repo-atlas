## 它是什么

ApkStart 是 Windows 10/11 x64 上的安卓应用运行器，目标是让安卓应用像 Windows 原生软件一样安装和使用。注册 `.apk` 文件关联后，双击 APK 就自动解析、安装并生成桌面图标；双击图标直接启动，应用出现在独立窗口里，而不是先打开一个模拟器管理界面。它面向想在桌面上单独使用某个安卓 App 的普通用户，也适合愿意折腾运行时参数的开发者。

它和 WSA、MuMu、雷电、蓝叠的路线不同。README 明确说 ApkStart 只用自带运行时，不探测、不接管也不驱动机器上已装的其它模拟器，设置里没有“切换引擎”选项。运行时组件由项目自己下载、校验和管理，壳层本身零第三方依赖，连 ZIP、PNG、ICO 和 Android 二进制 XML 的解析都是手写的。代价是安装包和首次部署都不小。

## 怎么上手

最省事的是下载现成包，GitHub 和 Gitee 两个源内容一致，README 建议国内用 Gitee。四种形态按需选：

- **商店版 MSIX**：从 Microsoft Store 安装，内置完整运行时，装完不联网，自更新交给商店。
- **完整便携版**：约 830 MB，解压约 1.3 GB，运行时全在包里，解压即用。
- **安装版**：约 1.3 GB，带桌面和开始菜单快捷方式、卸载项。
- **轻量便携版**：96 MiB，解压约 227 MB，首次启动再联网下载运行时。

轻量版第一次启动会下载 adb（约 8 MB）、Android Emulator（约 440 MB）和 Android 14 Google Play x86_64 系统镜像（源镜像约 3.1 GB，xz 后约 1.1 GB），可选的 AEHD 驱动约 0.2 MB。README 说官方源实测 10+ MB/s，下载支持 8 线程分块和断点续传，部署完成后自动开机。

从源码构建的步骤是 `npm install`、`npm start`（完成运行时部署）、可选的 `npm run assoc:on`（注册 `.apk` 双击安装），打包用 `npm run pack`，压缩发布必须用 `node build/zip.js`，README 明确说不要用 `Compress-Archive`，否则体积会大 5 MB、塞不进 Gitee。

常见卡点有三个。第一，没有硬件加速也能跑，但纯软件模拟开机会慢到几分钟；需要开的是 Windows 的“虚拟机监控程序平台（HypervisorPlatform）”，不是只给 WSL2 用的“虚拟机平台（VirtualMachinePlatform）”。第二，`adb devices` 看不到设备是正常的，ApkStart 的 adb 跑在专用端口 5044，要先设 `$env:ANDROID_ADB_SERVER_PORT = 5044`，不要手动连 5555。第三，`.apks` 和 `.xapk` 拆分包会自动用 `install-multiple` 安装，单独把里面的 split APK 拖进去不一定能用。

## 值得注意的设计

横竖屏适配是它重点解决的一处工程问题。模拟器的物理面板方向由 `hw.lcd.width/height` 决定，如果和应用声明的 `screenOrientation` 不一致，Android 只会给一个信箱式窄条，两侧补黑，改窗口大小或 `wm size` 都填不满。ApkStart 在安装时离线解析 `AndroidManifest.xml`，按启动 Activity 加权统计应用天然是横屏还是竖屏，存进 `apps.json`，启动时选对应面板：竖屏应用用 720×1280，横屏用 1280×720。它还把密度设成 190dpi，使 720 宽等于 606dp，刚好越过 Android 的 600dp 平板断点，红果短剧这类应用的双列布局才会出现；设置里的“平板排版”开关控制这个行为。只有面板方向和应用方向不一致时才重启运行时（约 40 秒），之后同方向的应用秒进。

窗口体验靠“把模拟器窗口嵌进宿主窗口”实现。README 说模拟器主窗不会单独出现在桌面上，要么被隐藏，要么用 `SetParent` 嵌进应用窗口；关闭时先把模拟器窗口从宿主摘下藏好，再销毁宿主，顺序反了 Windows 会把它重新挂到桌面。它还会按窗口类名和标题压制 `conhost.exe`、`netsimd` 等控制台窗口。这类细节决定了它看起来像原生应用还是像“套了个模拟器”。

运行时的数据路径也做了不少事。官方系统镜像里的 `userdata.img` 只是 1 MB 全零占位，直接拉 `emulator.exe` 会跳过格式化，导致 `/data` 挂不上、guest 掉进 recovery 循环。ApkStart 首次启动自己生成 4 KB block、带 `ENCRYPT` 和 `ext_attr` 的 ext4，再用自带 `qemu-img` 和 `resize2fs` 扩容。快照用只读基础层加薄可写层，空闲时保存 quickboot 快照，README 实测冷启动约 23 秒、命中快照约 10 秒；空闲预热默认开启，代价是常驻约 1 GB 内存。

更新链路不是死连 GitHub：同时查 GitHub 和 Gitee 的版本号取更高者，把直连、Gitee 资产和镜像前缀列为候选，每个地址真下 256 KB 测速，只算首字节之后的吞吐，再按速度分块并行下载。共享目录采用秒级双向同步而不是挂载，README 的解释是 Windows 无 root 时无法在安卓侧挂载 NTFS。

## 边界与风险

许可证是 MIT，但发行包只含 ApkStart 自身代码和 Electron 运行时，不分发安卓系统镜像、QEMU 二进制或 Google 组件；这些在用户本机首次启动时从官方源下载，各自遵循自己的许可协议。编辑判断：企业内分发时要确认这些运行时组件的授权，以及系统镜像中 GMS 的使用条款。

README 自己把项目定位为早期版本、作者业余维护、“暂时也不是很好用”。它只支持 Windows 10/11 x64，未提 Linux 或 macOS。硬件加速依赖 WHPX 或 AEHD，没有加速时虽然能用但启动很慢；完整运行时占 1.3 GB 以上磁盘，空闲预热还要约 1 GB 内存。ARM-only 应用需要开启“ARM 兼容模式”切到 Android 14 Google Play 镜像，README 说实测红果免费短剧可以运行，但个别应用内置更深的反模拟检测（如校验真实传感器或基带）仍可能失败。旧版 API 30 镜像上，字节系应用还会因非标准 signal handler 触发翻译层断言。

安全边界在用户一侧：APK 来源、应用权限和模拟器内的数据都由使用者负责。README 说安装后会自动授予应用申请的运行时权限、闪退时自动重试甚至重置数据，这对便利性有好处，但也意味着不要拿它运行来源不明的 APK。安卓侧通过 QEMU 用户态 NAT 复用主机网络，不创建虚拟网卡，减少了网络配置和驱动风险，但不等于隔离了应用对网络的访问。它适合折腾特定安卓 App 的个人，不适合需要长期稳定、可管理或企业级兼容层的场景。
