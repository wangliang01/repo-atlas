## 它是什么

Cal.com 是 Calendly 的开源自托管替代。日历同步、可用时间计算、团队轮询、Webhook 都在仓库里，部署后域名和数据都是自己的。

## 我的判断

我用 Docker Compose 起了一套，跑通「建事件类型 → 拿到公开链接 → 对方选时段 → 双方日历各多一条记录」这条主链路，花了一个下午，其中一半时间卡在邮件和 OAuth 的环境变量上。

它值得推荐的地方不是功能多，而是**主链路真的能跑通**：公开预约页不需要登录、时区换算没有明显错位、Webhook 能在对方确认后几秒内到达。不推荐给只想约人的个人，是因为自托管的运维成本（Postgres、邮件服务、OAuth 应用、升级迁移）远大于省下的订阅费。

## 技术看点

- **tRPC 贯穿前后端**：预约流程的入参和出参共用一份类型定义，前端改字段时后端不跟着改会直接编译失败，省掉了一整类联调问题。
- **可用时间计算单独成层**：日历忙碌块、工作时间、缓冲、最少提前量被拆成独立步骤，每一步可测，出问题能定位到具体一层。
- **多租户从第一天就在 schema 里**：团队、成员、事件类型都带归属，后面加组织和权限不用改表结构。

## 怎么上手

```bash
git clone https://github.com/calcom/cal.com.git
cd cal.com && cp .env.example .env
docker compose up -d
```

1. 起 Postgres 和 Web 容器，等迁移跑完
2. 打开 `http://localhost:3000`，注册第一个账号
3. 建一个 30 分钟的事件类型，复制公开链接，用无痕窗口走一遍预约

## 边界

**适合**：需要把预约数据留在自己环境、并且有人能维护一套 Web 服务的团队。

**不适合**：不想碰邮件服务和 OAuth 配置的个人；只需要「发个链接让人选时间」的场景，直接用官方托管更省事。
