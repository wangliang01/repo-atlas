## 它是什么

Uptime Kuma 是自托管的可用性监控。加一个 URL、设一个间隔，它就开始探活，挂了按你配的渠道告警，还带一个可以直接对外发布的状态页。

## 我的判断

它是我装过最省事的自托管服务之一：一条 `docker run`，两分钟进后台，五分钟内配好三个站点的探活和 Telegram 通知。

推荐的理由是**克制**。它不做 APM、不做日志、不做分布式探针，只回答一个问题：这个地址现在还通不通。代价也在这里——它只有单点探测，你在上海能连通不代表用户在法兰克福能连通；告警去重和值班编排也基本没有。所以我把它当"最后一公里的探活"，不当监控体系。

## 技术看点

- **探测结果按区间聚合**：心跳原始记录和 uptime 统计分开存，查 90 天可用率不用扫全表。
- **状态页与后台同源**：公开状态页是同一份数据的不同视图，不需要额外同步一条链路。
- **通知渠道插件化**：新增一个渠道就是实现一个发送函数，主流程不用改。

## 怎么上手

```bash
docker run -d --restart=always -p 3001:3001 \
  -v uptime-kuma:/app/data --name uptime-kuma \
  louislam/uptime-kuma:1
```

1. 打开 `http://localhost:3001`，设管理员账号
2. 添加监控项：URL、间隔 60s、重试 2 次
3. 配一条通知渠道，点「测试」确认能收到

## 边界

**适合**：想用一个容器解决"我的服务还活着吗"的个人和小团队。

**不适合**：需要多地域探测、SLO 计算、值班轮转的团队——那是 Prometheus + Alertmanager 的活。
