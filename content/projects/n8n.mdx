## 它是什么

n8n 是自托管的工作流自动化引擎。拖节点连成流程，把 Webhook、数据库、SaaS 和代码串起来，跑在自己的机器上。

## 我的判断

我起了一套，跑通了「Webhook 收消息 → 查库 → 条件分支 → 发飞书」这条链路，半天。功能上没有让我失望，但我给的是**观望**，不是推荐。

原因是它处在两个世界的夹缝里：比 Zapier 灵活得多，节点里可以直接写 JS、可以调 HTTP、可以自己写节点；但比写代码重得多——复杂分支在画布上很快变成一团线，改一个字段要来回点五层。我的结论是：**流程短、变化快、要可视化给非工程同事看**，它很合适；**流程长、逻辑复杂**，直接写代码更省命。另外它的协议不是标准开源协议，商用前要自己读一遍条款。

## 技术看点

- **节点是声明式的**：一个节点描述参数、输入输出和执行函数，UI 表单由参数描述生成，加节点不用改前端。
- **执行数据落库可回放**：每次运行保存每个节点的输入输出，失败能定位到具体节点并单独重跑。
- **可被代码调用**：工作流有 Webhook 和 API 两个入口，能从业务代码里触发，不必什么都做成定时任务。

## 怎么上手

```bash
docker volume create n8n_data
docker run -d --name n8n -p 5678:5678 \
  -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n
```

1. 打开 `http://localhost:5678` 建账号
2. 新建工作流：Webhook 节点 → 一个 HTTP 节点 → 一个通知节点
3. 用 `curl` 打 Webhook，看执行记录里每个节点的输入输出

## 边界

**适合**：需要把内部系统和外部 SaaS 串起来、且能接受自己运维一套服务的团队。

**不适合**：只做两三条简单同步的个人——这个体量用定时脚本更快；也不适合想完全免费商用的场景，协议要先看清楚。
