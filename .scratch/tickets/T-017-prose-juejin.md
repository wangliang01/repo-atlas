# T-017 正文排版对齐掘金实测值

## 背景

笔记页的 MDX 渲染还是「自己觉得好看」的版本：正文是灰的（`--muted` #6b7280），h2 18px 带上边框，行内代码是灰底加细边框，表格只有一条下边框。

用户看完第一周的笔记后连说三遍「这个写作排版，md 的格式渲染，也可以参考掘金的风格」。

## 实测

用 ego-browser 打开 `juejin.cn/post/7693821701955567670` 与一篇带代码的源码文，量 `getComputedStyle`：

| 元素 | 掘金 | 原来 |
|---|---|---|
| 文章标题 | 32px / 600 | 24px / 600 |
| 正文 p | 16 / 28（1.75）/ `#252933` / margin 22 | 16 / 28 / `#6b7280` / margin 16 |
| h2 | 22 / 34 / **700**，margin 35/10，padding-bottom 12，**下边框** `#ececec` | 18 / 600，上边框，pt-6 |
| h3 | 20 / 28 / 700，margin 35/10/5 | 16 / 600，mt-8 |
| 行内 code | 13.92px，`#ff502c` on `#fff5f5` | 13px，`--surface-2` + 边框 |
| 引用 | 16 / 28，`#666` on `#f8f8f8`，左 4px `#cbcbcb`，padding 1px 23px | 13px muted，左 2px accent |
| 链接 | `#0269c8` + `border-bottom` 0.8px `#d1e9ff` | 蓝色下划线 |
| 表格 | 表头 `#dff0ff` 底 / `#005bb7` 字，格子边框 `#c3e0fd`，padding 12px 8px | 只有行底边框 |
| 正文宽度 | 756 | 720 |

## 三个判断

**1. 正文不能用灰色。** 掘金正文是 `#252933`，和标题同色；灰只留给 meta。这一条改完，整页观感立刻从「文档」变成「文章」。

**2. 22 / 20 不能并进 UI 的六档。** `--text-h2` 现在是 18px，首页和列表的区块标题都在用；改到 22 会把首页的行数挤掉。掘金自己也是两套：UI 用 16/14/13/12，正文用 22/20/16。所以新增 `--text-prose-h2` / `--text-prose-h3`，只在 `[data-prose]` 里生效。

**3. 掘金的红字过不了 AA。** `#ff502c` 压 `#fff5f5` 只有 3.05:1，13.92px 的字需要 4.5。压深一档到 `#cf3c1a`（4.55:1），色相不变。暗色没有参照，按同色系往下压：`#ff8f70` on `#3a2420`（6.48:1）。

## 改动

- `app/globals.css`：新增 2 个正文字号、7 个正文颜色 token（`--code-ink` / `--code-bg` / `--quote-line` / `--link-line` / `--table-line` / `--table-head-bg` / `--table-head-ink`），两套主题各一份；行内代码改成红底红字；标题里的行内代码改为继承标题色。
- `components/prose.tsx`：按上表重写。
- `app/notes/[slug]/page.tsx`：标题从 24 提到 28（正文 h2 已经是 22，24 只差 2px，层次会塌）；「我还没搞懂的部分」跟着换成 22px 带下边框。
- `lib/tokens.test.ts`：字号测试改成「UI 六档 + 正文两档」；新增一组正文配色的 AA 断言。

## 踩到的坑

标题内代码的覆盖规则一开始写成 `[data-prose] :is(h2,h3) :not(pre) > code`，浏览器里 `matches()` 返回 false——`:is(h2,h3)` 和 `:not(pre)` 必须是两个不同的元素，而 code 的父元素就是 h2，中间没有夹层。改成 `[data-prose] :is(h2,h3) code` 才命中。

## 暗色核对（2026-11-22 补）

掘金只有浅色——用 CDP 模拟 `prefers-color-scheme: dark` 后它的计算样式和浅色完全一样，所以暗色这套没有参照，是自己配的。实测结果：

| 元素 | 暗色实测 | 对比 |
|---|---|---|
| 正文 | `#e5e6eb` / 16 / 28 | 卡片上 13.6:1 |
| 行内代码 | `#ff8f70` on `#3a2420` | 6.48:1 |
| h2 下边框 | `#2f3033` | 装饰 |
| 引用 | `#9aa1ad` on `#2a2b2e`，竖线 `#4a4c52` | 文字 5.44:1，竖线 1.65:1 |
| 表头 | `#8cc4ff` on `#1b2b3f`，格线 `#2f4a6b` | 7.82:1 |
| 示意图 | 问块 `--accent-soft` + `--accent` 边，答块 `--surface-2` + `--line` 边 | 文字 6.1 / 5.4:1 |

一处调整：引用竖线原来是 `#3f4045`（1.37:1），比浅色的 `#cbcbcb`（1.53:1）还弱，压到 `#4a4c52`（1.65:1）——同样的观感强度，深色下要多给一点。

留了个判断没改：行内代码在暗色下是暖棕色底，和全站冷灰调有点冲。但这是掘金红底红字的延续，去掉底就丢了「这是个标识符」的提示，暂时保留。
