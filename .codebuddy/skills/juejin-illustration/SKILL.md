# 技术文章配图

配图不是给文章加装饰，是替一段说不清的话省下三百字。所以顺序是：先判断要不要图，再决定画哪种，最后才是怎么画。

## 一、先判断配不配

拿实测数据当基准。七篇样本里配图量差得很远：

| 模式 | 代表 | 图数 | 图是什么 |
|---|---|---|---|
| A 认知纠错 | ErpanOmer | 8 | 概念示意图为主 |
| B 体系化长文 | 大漠 | 1 | 一张总览表 |
| C 问题驱动 | 熊的猫 | 6 | 现场截图 |
| C 问题驱动 | kyriewen | 0 | 全文字，靠代码块 |
| D 清单测评 | 涛涛ing | 0 | 全文字 |

**没有「每篇必须配几张」这回事。** kyriewen 那篇 5670 字零图，照样是样本里最好读的一篇——因为它在讲判断逻辑，没有空间关系要表达。

判断标准只有一条：

> 这段话里有没有「谁挨着谁」「谁在谁里面」「先后顺序」这类关系？

有，就配图。没有，就别配。硬配出来的图会让读者跳过正文去看图，然后什么也没记住。

按模式给个预算，超了就是凑数：

- **A 认知纠错**：每 800–1000 字一张，用来把「你以为的」和「实际的」并排放
- **B 体系化长文**：3–5 张，每张负责一个分类树，不要每节都配
- **C 问题驱动**：0–6 张，优先用真实截图（报错现场、调试面板、前后对比）
- **D 清单测评**：每节最多一张，截图优先，没有就空着

## 二、三种图，三条产线

### ① 示意图 —— 内联 SVG，写在 MDX 里

结构图、流程图、时序图、对比图都走这条。**必须内联，不能引用外部 svg 文件。**

原因是硬性的：`<img src="x.svg">` 加载的是独立文档，拿不到页面的 CSS 变量，也没法继承 `currentColor`。暗色模式下它不会跟着变，白底黑字的图会直接糊在深色卡片上。

写法：`<Figure>` 包一层，里面直接写 `<svg>`。属性用 JSX 驼峰（`textAnchor`、`strokeWidth`、`fontSize`）。

```mdx
<Figure caption="第 3 轮的请求里装着前两轮的全部内容。">
  <svg viewBox="0 0 300 200" className="mx-auto block w-full max-w-[420px] py-3" role="img">
    <title>三轮对话的请求内容，逐轮变长</title>
    <rect x="11" y="32" width="50" height="32" rx="3" fill="var(--accent-soft)" stroke="var(--accent)" />
    <text x="36" y="53" fontSize="11" textAnchor="middle" fill="var(--accent-ink)">问 1</text>
  </svg>
</Figure>
```

颜色只能用 token，不许写十六进制：

| 用途 | 填 | 描边 | 字 |
|---|---|---|---|
| 主对象（问题、输入、触发） | `var(--accent-soft)` | `var(--accent)` | `var(--accent-ink)` |
| 次对象（回答、结果、旁支） | `var(--surface-2)` | `var(--line)` | `var(--muted)` |
| 说明文字、轴标签 | — | — | `var(--muted)` |

尺寸按这条定：**viewBox 宽度写 300–360**。375px 手机上正文可用宽度约 293px，这个区间缩放比在 0.8–1.0 之间，11px 的字落到屏幕上还有 9–11px，看得清。写 600 宽再缩到 293，字就只剩 5px，等于没写。

其余约束：

- 字号最小 11，`<text>` 里不要放长句，一句话拆成标签
- 每个 `<svg>` 带 `<title>`，读屏器靠它念
- 方块之间的间距至少 7，太挤在手机上会粘成一条
- 不要画阴影、渐变、3D 透视——这套 token 里没有这些东西，画出来跟全站不是一个语言

### ② 真实截图 —— png，放 `public/shots/<笔记 slug>/`

终端输出、devtools、接口返回、页面前后对比，都走这条。

```
public/shots/llmops-token-context/
  usage-panel.png
  before-after.png
```

正文里用 `![alt](/shots/llmops-token-context/usage-panel.png)`。

`proseComponents` 已经给 `img` 加了懒加载、圆角、边框和 `w-full`，不用自己写样式。

**alt 必须写。** `pnpm check:alt` 会扫构建产物，缺 alt 直接退出码 1。只有纯装饰图（旁边文字已经说完了）才允许 `alt=""`，这种会被单独计数打出来——偶尔一两张正常，多了说明在偷懒。

截图的三条要求：

- 2 倍图。容器宽 720，截 1440 宽起步，否则在高分屏上是糊的
- 只截有用的区域。整屏截图里读者要自己找重点，等于没截
- 不要打码到看不出所以然。密钥、内网地址要么裁掉，要么整段替换成假值再截

### ③ 封面 / 氛围图 —— 基本不用

这个站是证据页，不是内容平台。封面图不承担任何信息，只会让列表变慢。

真要生成，注意 `mcp__craft-anything__assets_image_generate` 的 `save_as` 是相对 `app/` 的，而本站静态资源在 `public/`——路径对不上，存进去的图不会被当作静态文件服务。要用得先确认落盘位置，别直接调。

## 三、红线：技术示意图不许用 AI 生图

AI 生图里的代码、变量名、箭头方向、坐标轴刻度，全是「看起来对」的错。它能把 `for` 写成 `f0r`，把箭头指反，把两个本不相连的框连起来。

**一张错的图比没有图更糟。** 读者会记住图，不会记住你后面那句「注意方向」。

所以：示意图要么手写 SVG，要么用真实截图。没有第三条路。

## 四、图注写法

图注回答的是「这张图证明了什么」，不是「这张图是什么」。

- ✗ 「图 1：请求结构示意图」
- ✓ 「第 3 轮的请求里装着前两轮的全部内容。三轮下来送了 9 个块，内容其实只有 5 个。」

一句话，60 字以内。图注里可以出现数字，但不许重复正文里紧挨着的那句话——重复了就该删图注，或者删那句话。

## 五、自检

- [ ] 把这张图删掉，这段还读得懂吗？读得懂就删掉
- [ ] 图里每个字在 375px 下还能看清吗？
- [ ] 切到暗色，图还看得见吗？
- [ ] 图注说的是结论，还是「示意图」三个字？
- [ ] 有没有哪张图是 AI 生成的、里面带着假代码或假箭头？
- [ ] `pnpm check:alt` 过了吗？

## 六、和 juejin-writing 的关系

先按 `juejin-writing` 定模式和骨架，写完正文再回头看哪里需要图。

顺序反了会出问题：先画图再写文，图会变成文章的主线，正文退化成图注。
