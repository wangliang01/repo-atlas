# 掘金技术写作

写出来的东西要像一个真跑过的人在讲，不像一个模型在总结。三件事按顺序做：定模式 → 填结构 → 过自检。

## 一、先定模式

三种模式来自三位作者的实测样本，各自解决不同问题。选错模式比写不好更致命。

| 模式 | 什么时候用 | 代表作者 |
|---|---|---|
| **A 纠错型深挖** | 题目被写烂了，但读者普遍有一个盲区 | ErpanOmer |
| **B 问题驱动** | 排障、架构取舍、需求变更——有具体现象要解释 | kyriewen |
| **C 工具测评** | 新库 / 新框架 / AI 工具，读者要判断值不值得用 | 涛涛ing |

本站笔记的默认选择：**源码与架构用 B，被写烂的经典题用 A，工具类用 C**。一篇只用一个模式，不要混。

### A 纠错型深挖

```
标题：绝对化承诺，但要有依据（"这篇你看完就不用再看别的了"）
开头：承认读者已经看过很多 → 指出他们的共同盲区 → 承诺一个具体收获
正文：把机制拆成可执行步骤（第一步…第九步），每步配代码或图
结尾：回到真实工作场景（"这些知识在真实工作中怎么用？"）
```

样本实测：6500 字 / 15 个代码块 / 8 张图 / 26 处加粗 / 平均段 29 字。

### B 问题驱动

```
标题：一个真实问句 + 后果（"AI 能把页面写出来，为什么改个需求就开始崩？"）
开头：直接给现象，不铺垫、不介绍背景
正文：H2 编号 1..N，每个标题是一句结论，不是名词短语
结尾：参考资料或可执行动作，不做总结陈词
```

样本实测：5700 字 / 8 个代码块 / 0 张图 / 8 处加粗 / 平均段 33 字。

### C 工具测评

```
标题：数字钩子 + 收益（"4.8K Star！一套规则让 AI 帮你写出像人写的代码"）
开头：一句判断，不是行业背景
正文：一、二、三…每节回答一个问题；核心功能用 H4 拆开
结尾：链接 + 一个真问题（不是"欢迎交流"）
```

样本实测：4000 字 / 5 个代码块 / 0 张图 / 38 处加粗 / 平均段 32 字。

## 二、硬规则

这些是三条样本的共同点，违反任何一条都会立刻露出"生成"的味道。

1. **标题 ≤ 22 字**，必须含一个具体名词或数字。禁用「浅谈 / 漫谈 / 一文读懂 / 深入浅出」。
2. **第一句不能是背景**。不写「随着…的发展」「在当今…」。第一句要么是一个判断，要么是一个场景。
3. **小标题是句子，不是名词**。写「全选框亮不亮，不能看有没有选中项」，不写「全选框状态管理」。
4. **每段 1–3 句**。样本平均 29–33 字一段，超过 4 句就拆。
5. **每个抽象结论，200 字内必须跟一个可验证的东西**：代码、命令、输出、数字、截图。没有就不写这个结论。
6. **代码块前一句说这段在干什么，后一句说输出是什么**。不贴裸代码。
7. **加粗只给结论句**，一段最多一处。样本从 8 到 38 处不等，但每一处都是判断句。
8. **不用「首先 / 其次 / 最后」串全文**。用编号、步骤，或直接分段。
9. **结尾不写「希望对你有帮助」**。给一个动作、一份资料，或一个没解决的问题。

## 三、句子层

- 用「你」指读者，用「我」指自己。样本里两种人称都很密。
- 短句优先。一句话说不完就断成两句，不要靠逗号串。
- 具体数字胜过形容词：「快 12 倍」而不是「快很多」；「3 个 G」而不是「大量」。
- 允许口语（「我差点儿没瞎」「先别急着抄」），但不允许网络烂梗堆叠。
- 不确定的地方直接写「这点我还没搞懂」。本站笔记的 `kind` 里本来就有「重建」，半成品是允许的。

## 四、自检清单

写完逐条过，有一条不过就改：

- [ ] 遮住标题，只读第一段，还知道这篇在讲什么吗？
- [ ] 每个 H2 单独拿出来，是不是一句能立住的话？
- [ ] 每个抽象结论后面，有没有一个能点开核对的东西？
- [ ] 删掉所有形容词，还剩多少信息？
- [ ] 有没有哪一段超过 4 句？
- [ ] 加粗的是判断句，还是随便强调的词？
- [ ] 结尾是不是「希望对你有帮助」这类废话？
- [ ] 通篇有没有出现「首先/其次/综上所述/值得注意的是」？

## 五、反例

这些句子一出现，整篇的可信度就没了：

- 「在当今快速发展的互联网时代…」
- 「本文将深入浅出地介绍…」
- 「总的来说，X 是一把双刃剑」
- 「不仅…而且…更重要的是…」（三段式排比）
- 「让我们一起探索…」
- 用三个并列短句凑节奏：「更快、更稳、更强。」

## 六、写本站笔记时的落地

笔记是 MDX，frontmatter 四个字段全必填，缺一个构建就失败：

```yaml
---
title: 为什么这个站用 MDX 而不是 CMS
summary: 一句话说清这篇解决什么问题
kind: tool        # source | architecture | rebuild | tool
publishedAt: 2026-11-22
---
```

`kind` 决定列表页的分组，选错会让左栏出现空锚点。正文里可以用 `<Callout>`、`<CodeBlock>` 等已有组件，不要自己造。
